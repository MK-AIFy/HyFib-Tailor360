Sub-issue of #52. The parent's seventh implementation step — "Implement image optimization, lazy loading,
virtualization/pagination and bundle splitting **based on measurement**" — and the half of its fourth acceptance
criterion that actually moves a number. The plan is emphatic about the order: "**Optimisations (measured first, then
applied)**", which is why this is a separate sub-issue from **[E12-F03-6]** and starts from its baseline. The gap is
checkable: `clients/pwa/src/app/router.tsx` is 425 lines in which **every one of the route components is a static
import** — `grep -n "lazy\|import(" src/app/router.tsx` returns nothing — so a Tailor opening the application on the
reference phone downloads, parses and executes `CatalogDesignRoute` (1,269 lines), `MeasurementDraftRoute` (1,020),
`CatalogVersionEditorRoute` (994), `TemplateVersionEditorRoute` (848) and every admin and billing screen before the
first paint. `qrcode-generator` is in that same initial bundle for everybody, and
`grep -rn "qrcode-generator" clients/pwa/src` shows exactly one importer: `src/auth/QrCode.tsx`, the authenticator
enrolment screen.

## What is already built (do not re-build)

- `docs/nfr/performance-report.md` and the `size-limit` and Lighthouse CI configurations — **[E12-F03-6]**. The
  baseline, the gates and the "after" column this sub-issue fills in all exist before it starts. **Do not add a
  second budget, do not change a limit, and do not relax one to make a change land.**
- `clients/pwa/vite.config.ts` — `manualChunks` already emits `vendor-intl` (react-intl, `@formatjs`,
  `intl-messageformat`), `vendor-router` (react-router) and `vendor`, with a comment explaining the ordering trap
  ("react-intl and react-router both contain 'react'"). Extend that function; keep the ordering comment true.
- `clients/pwa/src/components/states/LoadingState.tsx` and `StateRegion.tsx` — the existing loading surface. A
  route's `Suspense` fallback is `LoadingState`, not a new spinner, and it is announced the way
  `clients/pwa/CLAUDE.md` section 4 requires ("Status is announced through a polite live region").
- `clients/pwa/src/routes/admin/AuditTrailRoute.tsx` lines 40 to 152 — **cursor pagination already works**:
  `cursors`, `nextCursor` and an explicit "show more" control rather than an infinite scroll that re-orders under
  the user's hands. This is the pattern `docs/nfr/capacity-and-performance.md` section 7 calls for
  ("Server-driven pagination with cursors, never client-side filtering of a whole table"), it is already in place,
  and this sub-issue does not replace it with virtualisation.
- `clients/pwa/src/App.test.tsx` — it imports `DisplaySettingsRoute`, `HomeRoute` and `NotFoundRoute` as **named
  exports** from `src/app/router.tsx` and builds an in-memory copy of the route table. Those three must stay eager
  named exports or that test breaks; the change is to the other routes.
- `clients/pwa/src/app/accessibilityCoverage.ts` and the exported `routeTree` — **[E12-F03-2]**. A lazily loaded
  route must still appear in the coverage list, and that test is what proves it does.
- `docs/nfr/capacity-and-performance.md` section 7 — the eight practices "the budgets in section 3.3 are only
  achievable with … recorded so that a future change that breaks one is recognised as a budget change rather than a
  refactor". This sub-issue implements the first, fourth and eighth of them and records which of the rest have no
  subject yet.

## What is missing

- No route-level code splitting at all, which is the first practice of section 7 and the reason the initial-bundle
  row of section 3.3 is the budget most likely to be red at the baseline.
- `qrcode-generator` is in the entry chunk although exactly one screen uses it.
- `manualChunks` splits vendors, but because every route is a static import there is no dynamic boundary for Rollup
  to split application code at, so application code has no chunk boundaries at all.
- The "after" column of `docs/nfr/performance-report.md` is empty, so `RG-07`'s before-and-after evidence is half
  written.

## Scope

- [ ] Convert the route table in `clients/pwa/src/app/router.tsx` to `React.lazy` per **feature area**, not per
      route: one dynamic import boundary for the admin area, one for catalogue, one for measurements, one for
      billing, and one for the authenticator enrolment screen. Keep eager: `App`, `AuthShell`, the four
      authentication routes, `HomeRoute`, `InstallRoute`, `AboutRoute`, `DisplaySettingsRoute` and
      `NotFoundRoute` — the first paint and the unauthenticated surface. `HomeRoute`, `DisplaySettingsRoute` and
      `NotFoundRoute` stay **named exports** of this file, because `src/App.test.tsx` imports all three.
- [ ] Wrap each lazy boundary in `Suspense` with `LoadingState` as the fallback, inside the shell so the navigation
      stays on screen while a chunk loads, and with the fallback announced politely. A chunk that **fails** to load
      — the offline case — renders `RetryableError` with a Retry that reloads the chunk, not the page, and never
      discards typed input; a blank screen or an unhandled rejection is the failure this wrapping exists to prevent.
- [ ] Touch `manualChunks` in `clients/pwa/vite.config.ts` **only** for `vendor-qrcode`. The feature-area chunks do
      **not** need a `manualChunks` entry: Rollup emits one chunk per dynamic import boundary on its own, and the
      function returns `undefined` for anything outside `node_modules` at line 67, so application code is already
      left to the bundler. Adding application paths to that function would fight the dynamic boundaries rather than
      help them. Keep the existing vendor ordering and its comment intact — it says "Order matters: react-intl and
      react-router both contain 'react'" — and put the new branch **after** those two and **before** the final
      `return 'vendor'`. Name the emitted chunks in the pull request so `size-limit`'s per-route entries can be
      pointed at them.
- [ ] Move `qrcode-generator` behind a dynamic import inside `clients/pwa/src/auth/QrCode.tsx`, so the decoder is
      fetched when the enrolment screen renders and not before. The component's existing behaviour, accessible
      name and tests do not change; its loading state is `LoadingState`, and its failure state is the same
      `RetryableError` path, because an enrolment that silently shows no code is worse than one that says it could
      not load.
- [ ] Re-measure with **[E12-F03-6]**'s own commands and fill in the "after" column of
      `docs/nfr/performance-report.md` for every budget this changes, with the commit and the date, plus a short
      "what moved and why" note per row. A row that did not move says so; a row that got **worse** says so, loudly,
      with the issue raised.
- [ ] Record in the report which practices of `capacity-and-performance.md` section 7 have **no subject yet**, with
      the issue that will give them one, instead of implementing them speculatively: list virtualisation for the
      workboard, the delivery queue and the stock ledger (**#33**, **#48**, **#39** — none of those screens exists at
      HEAD); no image decoding in the browser and responsive derivatives with `srcset` (**#31** and **#189** — the
      client renders no derivative today and `grep -rn "srcset" clients/pwa/src` finds none); one camera stream at a
      time (**#36**); the font subsetting and `font-display: swap` row (**no web font is loaded at all today** —
      `grep -rn "@font-face" clients/pwa/src/styles` returns nothing and `clients/pwa/public` holds only `icons`,
      `manifest.webmanifest` and `screenshots`, so the Tamil and Latin subsets arrive with the localisation work of
      **#50**); and the stale-while-revalidate allowlist (**#51**).
- [ ] Confirm, and record in the report, that cursor pagination is already the default on the lists that exist —
      naming `AuditTrailRoute` lines 40 to 152 as the implementation — so that "pagination" in the parent's seventh
      step is recorded as **already satisfied**, not silently skipped.
