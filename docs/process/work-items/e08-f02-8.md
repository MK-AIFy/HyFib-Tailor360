Sub-issue of #39. The plan's Lane B line for #39 lists five screens ("purchase order/receipt entry … 'Record material'
panel … item balance card with transaction timeline; location transfer; ledger browser", `docs/IMPLEMENTATION_PLAN.md`
Section 9, `### #39`), and the client has none of them: there is no `clients/pwa/src/inventory/` and no
`clients/pwa/src/routes/inventory/` directory, `docs/api/openapi.v1.json` contains no `api/v1/inventory` string, and
`clients/pwa/src/components/layout/roleNavigation.ts:78` already sends the Inventory Clerk to `/inventory` — a
destination `clients/pwa/src/app/router.tsx` never defines, so it is a client 404 today. This child builds the two
**read** screens: what is on the shelf, and how it got there. It is the cheapest of the three client slices and
establishes the pattern the other two inherit.

- **Formatting, and the one import a session gets wrong here.** `clients/pwa/src/i18n/formatters.ts` exports **no**

  (declared `:117`, implemented `:279`), alongside `formatNumber` (`:109`), `formatMoney` (`:111`), `formatDateTime`
  (`:126`), `formatLongDate` (`:120`) and `formatRelativeTime` (`:128`). You obtain the set and then call the member.
  Two accessors exist:
  - `getFormatters(locale = DEFAULT_LOCALE, timeZone = DEFAULT_TIME_ZONE)` (`:361`), cached per locale — what every
    built billing route uses, always with **no argument**, e.g. `OutstandingBalancesRoute.tsx:22` (`const formatters =

  - `formattersForLocale(locale)` in `clients/pwa/src/design-system/components/forms/formatting.ts` — "the formatter
    set for whatever locale react-intl is currently rendering", which also maps the pseudo-locale back through
    `resolveLocale` so a pseudo-locale story still shows real numbers.

  **Use `formattersForLocale(useIntl().locale)` on both screens**, so the figures follow the display locale, and say
  in the pull request that the billing routes call `getFormatters()` with no argument — matching the locale here is a
  deliberate improvement and **no existing file is changed for it**. Every quantity goes through
  `formatters.formatQuantity(value, unitSymbol)`; no inline `toFixed`, no `Intl` constructed in a component.

(`E08-F02-10b`); a reservation gets no screen in #39 at all. The item, supplier, location and reorder-rule admin
screens — #38's client children (`[E08-F01-5]` to `[E08-F01-8]`). **CSV export of the ledger**: there is no CSV writer
anywhere in `src/` and no export endpoint to call; stock exports belong under `reports.export` with expiry and audit
(`docs/nfr/data-classification.md` section 5.9) and are #46's governed exports. Scanning an `S-` label to find an item
(A11Y-RJ-05 step 2) needs #36's scanner, which does not exist; the item is reached here by navigation and by the admin
item list. Low-stock queues and valuation screens are #40. Any service worker, offline cache or queued read: there is
none in the application (`OfflineBlockedAction` is the only offline behaviour) and #51 owns that.

## Acceptance criteria

- [ ] An Inventory Clerk holding `inventory.view_reports` opens `/inventory/items/:itemId/stock`, sees each location's
      on hand, reserved, available and in transit **as a quantity with its unit**, and the consumed figure for the
      branch; every number and instant on the screen came from a `Formatters` member, with no inline formatting.
      Proved two ways: by reading the diff, and by a test that renders under `ta-IN` and asserts a **long date** shows
      Tamil month names (`formatters.ts:120`: "`04 September 2026`, with Tamil month names in `ta-IN`"), which only
      passes if the screen took its formatters from `formattersForLocale(useIntl().locale)`. **Do not assert a
