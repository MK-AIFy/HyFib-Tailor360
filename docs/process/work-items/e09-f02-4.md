- [ ] **Read calls** in `clients/pwa/src/billing/billingApi.ts`: `getInvoice(invoiceId, signal)` through
      `apiRequestVersioned<Invoice>` so the `ETag` is kept for the write slices (#42's later children send it as
      `If-Match`), and `resolveInvoiceBarcode(payload, signal)`.
- [ ] **`InvoiceRegisterRoute`** at `clients/pwa/src/routes/billing/InvoiceRegisterRoute.tsx`, route
      `billing/invoices` under `RequirePermission permission={BILLING_PERMISSIONS.createInvoice}` in
      `clients/pwa/src/app/router.tsx`: the branch's invoices newest first in a `DataTable` (order number, invoice
      number or "draft", customer display name, grand total, status, created date), a `Filters` control over the
      three status names, and **Show more** following `nextCursor` until the server answers null. Page size is
      `InvoiceListQuery.DefaultLimit`; the control never offers more than `MaximumLimit`.
- [ ] **Barcode lookup on the register**: a labelled field that accepts a scanned or typed `I-` payload, calls
      `resolveInvoiceBarcode` and navigates to the resolved invoice's detail route. A refusal is rendered as text,
      never as a code (`clients/pwa/CLAUDE.md` section 4). The field is a plain text input — **no camera and no
      wedge-scanner integration in this slice** (that is Custody's, #190–#197).
- [ ] **`InvoiceDetailRoute`** at `clients/pwa/src/routes/billing/InvoiceDetailRoute.tsx`, route
      `billing/invoices/:invoiceId` under the same permission: the header (number or "draft", status, order number,
      financial year, posted date, customer block), the lines table (line number, description, quantity, applied
      rate, discount, taxable value, HSN/SAC classification — the payload field is `classification` — the
      CGST/SGST/IGST/cess components each with its rate and amount, line total), the document totals, the
      cancellation banner when `cancelled` is true, and the credit and debit notes with their numbers, reasons and
      totals.
      **The totals block follows the rendered document's own suppression rule**, so the screen and the PDF agree:
      `BillingDocumentTemplate.cs` prints `Taxable value` and `Grand total` always (they are its two emphasised
      lines) and **omits `Discount`, `CGST`, `SGST`, `IGST`, `Cess` and `Round-off` when they are zero**. Render the
      same way — nine fields exist on `InvoiceTotalsPayload`, but an intra-state invoice never shows IGST and a
      whole-rupee invoice never shows a round-off, and a screen that prints `₹0.00` rows the document does not is a
      screen the accountant's comparison fails on.
- [ ] **Problem messages** for the refusals a person can act on, added to
      `clients/pwa/src/billing/billingProblems.ts` and `clients/pwa/src/i18n/messages/billing.ts`:
      - `billing.invoice-not-found` → already mapped to `billing.problem.invoiceNotFound`; the detail route's
        refusal for an unknown identifier. Reuse it, do not re-map it.
      - **`billing.document-not-found` → a new `billing.problem.barcodeNotFound`**, the one sentence the lookup
        renders for all four indistinguishable cases (another branch's invoice, another organisation's, a payload
        whose check character does not hold, and a payload matching nothing), because that is the single code the
        route answers for all four by design (matrix row 379, and `ResolveInvoiceBarcode`'s own description).
      - **`billing.value-required` with field `branch`** → a sentence saying the lookup needs a branch for the session,
        for the case where the signed-in session carries no branch. This is a validation problem, not a not-found,
        and it is the only other answer the route has.
- [ ] **Messages** in `clients/pwa/src/i18n/messages/billing.ts` for both screens, added to `billingEn` **and**
      `billingTa` (the Tamil entry carries the English string with the `// not translated — awaiting
      native-speaker review` comment the file already uses). Every amount goes through
      `getFormatters().formatMoney`, every rate through `formatPercent`, every date through `formatShortDate`;
      never `toLocaleString` at a call site (`clients/pwa/CLAUDE.md` section 5). This is configuration-free work:
      no seed data and no versioned configuration is involved (DOR-11).
- [ ] **Styles** in `clients/pwa/src/routes/billing/billing.css` only; the lines table scrolls inside its own
      container so there is no horizontal page scroll at 320 CSS px.

## Acceptance criteria

- [ ] A Cashier holding `billing.create_invoice` opens `/billing/invoices`, sees the branch's invoices newest
      first with amounts formatted `₹1,23,456.78`, filters to `Posted`, presses **Show more** and sees the second
      page appended — all over HTTP through `apiClient`, with no direct database access.
- [ ] Opening a row reaches `/billing/invoices/:invoiceId` and shows the invoice's lines, every tax component with
      its rate, the totals block under the document's own suppression rule (taxable value and grand total always;
      discount, CGST, SGST, IGST, cess and round-off only when non-zero, the round-off with its sign), and — for a
      cancelled invoice — a banner saying it is cancelled while the number and totals still stand.
- [ ] Pasting a valid `I-` payload into the register's lookup field navigates to that invoice's detail route.
- [ ] **Negative:** a signed-in person holding no billing permission is refused the register and the detail route by
      `RequirePermission` before any request is made, and the server refuses the same two reads with `403` when
      called directly — asserted in the route tests through `aCurrentUser({permissions: []})`.
- [ ] **Negative:** a payload for another branch's invoice, a payload for another organisation's, a payload with a
      broken check character and a payload that matches nothing all render the **same** sentence, because the server
      answers all four as **`billing.document-not-found`**; the screen never says "exists but not yours", and it
      never renders the code.
- [ ] **Negative:** a session carrying no branch gets the lookup's other answer — `billing.value-required` with
      field `branch` — rendered as its own sentence about needing a branch, not as the not-found sentence.
- [ ] **Exception:** with the network down, both screens render `NetworkStatusBanner` and the register's **Show
      more** and the lookup field do not silently queue anything — billing is online-only
      (`clients/pwa/CLAUDE.md` section 6). A read that fails renders `RetryableError` with a working retry, and a
      retry does not lose the chosen status filter or the typed payload.
- [ ] Both screens pass `expectNoAccessibilityViolations` at the phone, tablet and desktop profiles, and the lines
      table answers checklist records **A11Y-BI-01** to **A11Y-BI-06** (currency on every amount, Indian grouping
      read as one amount, each amount announced with its line, CGST and SGST separately with rate and amount, the
      total announced with the word "Total", the round-off announced with its label and sign). **A11Y-BI-06 is
      answered on an invoice that has a non-zero round-off** — choose the fixture deliberately, because a zero
      round-off is not rendered at all.
