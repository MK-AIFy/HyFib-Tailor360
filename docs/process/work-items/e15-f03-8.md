  it, when it was last run ("Never"), who runs it, the prerequisite and the evidence expected; a "what a step is
  asking" section; then journeys as tables of action, expectation and *a question for the person running it*. Its
  closing rule is the one that matters: "a step that only checks the software would be an integration test, and

## Data and classification

Per `docs/nfr/data-classification.md` section 2. A user-acceptance script is a document that tells a person to look
at personal data on a screen, so the classification that matters is the **evidence** it asks them to capture.

| Item | Class | Purpose | Retention | Who may read it | Logs, telemetry, export |
| --- | --- | --- | --- | --- | --- |
| The scripts themselves | Internal | Tell a named role what to do and what to judge | As the repository | Anyone with repository access | Synthetic data only, per `docs/prd/walkthroughs.md` section 1.2 |
| Screenshots captured while running a script | **Personal** — they render a customer record | Evidence for `RE-15` | With the release record | The Owner, the technical reviewer, the signatory | Taken against synthetic data; where a run on a pilot environment shows a real customer, the personal data is edited out before the screenshot is attached, per `docs/security/role-walkthrough.md` section 7. The script says this at the top, not in a footnote |
| Measurements a Measurement Staff script captures | **Sensitive personal** | Exercise the capture wizard and the version model | As the repository | As above | Synthetic figures only. A measurement never appears in a log, a trace or a pull-request comment (`CLAUDE.md` section 4 rule 7) |
| Problem-details bodies captured for a refusal | Internal | Prove the refusal was readable and carried a correlation identifier | With the release record | As above | The correlation identifier is the point; the body must carry no stack trace and no raw exception message (`CLAUDE.md` section 4 rule 3) |
| The signature block entries | **Personal** — a named person and a date | Prove who accepted what | As the release record; see the audit retention row of `docs/nfr/data-classification.md` section 5.11 | The Owner and the reviewer | A name and a role, never a signature image, never contact details |
