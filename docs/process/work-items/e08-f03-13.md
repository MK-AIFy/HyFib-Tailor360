Sub-issue of #40. **This is not a coding session. It produces no code, no migration and no endpoint.** It exists
because #40's fifth acceptance criterion — "Valuation methodology and rounding pass **accountant-approved**
scenarios" — needs a human signature, and a signature is not something a coding agent can produce or wait for. Giving
it its own issue means `E08-F03-7` can merge on green tests without anybody pretending the accountant has reviewed
anything, and the parent's AC5 has a place to close.

The precedent in this tracker is established: `E07-F01-9` ("Printed label evidence: printer, device and durability
records") and `E15-F03-8b` ("the money and oversight UAT scripts and the accountant's billing approval") are both
evidence children of exactly this shape, and `E09-F02-10` explicitly "prepare[s] the accountant's review".

## Acceptance criteria

- [ ] `docs/inventory/valuation.md` carries a dated sign-off naming the reviewer, the commit reviewed and what was
      accepted — or, if the review found problems, the list of them with a defect raised for each on the issue that
      owns it.
- [ ] Every file under `tests/fixtures/inventory/valuation/` either carries confirmed numbers with the
      "pending sign-off" marker removed, or is listed in the sign-off record as still outstanding with a reason.
- [ ] `docs/prd/assumptions-and-open-decisions.md` records the outcome of OD-05's **valuation** half, in the register's
      own shape, whichever way it went.
- [ ] **Negative:** if any replaced figure makes a test fail, the suite is left **red in a defect on `E08-F03-7`** and
      the figure is not adjusted to make the test pass. The whole value of an accountant's number is that it was not
      chosen to agree with the code.
- [ ] **Negative:** no waiver is written in `docs/process/waivers.md` for the absence of a sign-off, and no release
      gate is marked met on the strength of a green test run.
- [ ] **Exception:** if the accountant accepts weighted average and declines FIFO (or the reverse), the outcome is
      recorded as a **decision**, the unused method stays implemented and tested, and nothing is deleted — a method
      that is configuration cannot be removed because one shop does not use it
      (`docs/prd/configurable-vs-fixed.md` line 72: "Valuation method — weighted average or FIFO — and its
      configuration version … Past valuation runs are immutable").
