Sub-issue of #56. Plan Section 7 row `#56a` ends with "severity gates and **licence audit** in CI", and
`docs/process/release-gates.md` `RG-08` already treats "a licence outside the allowlist" as an **S1 blocking**
failure — the strongest severity the gate catalogue has. There is no allowlist and no audit:
`ls .github/licence-allowlist.json scripts/licence-audit.py` returns two "No such file or directory" lines, and
`grep -rni "licen" .github/workflows/ci.yml` finds only the gitleaks licence *key*. So `RG-08` cites a control that
does not exist, and the one artefact that would make it cheap is already produced and thrown away: the `sbom` job
writes a CycloneDX document with per-component licence metadata to `artifacts/sbom/tailor360.cyclonedx.json` and
**nothing reads it**.

This sub-issue adds the one scan the repository has never had. It is separated from its sibling — the
vulnerability-management process, the `SEC-EX-nnnn` exception register and the expiry rule in `scripts/sarif-gate.py`
— because the two have disjoint file sets (this one owns `ci.yml` and `RG-08`, that one owns `sarif-gate.py` and
`waivers.md`), so they can be taken in either order and in parallel.

## What is missing

- No allowlist, so "outside the allowlist" has no meaning and `RG-08`'s S1 clause is unenforceable.
- No reader of the CycloneDX document, so a dependency that arrives with a copyleft or an undeclared licence reaches
  `main` unnoticed. A transitive dependency is the realistic case: nobody chose it and nobody looked at it.
- Nothing distinguishes "no licence declared" from "a licence we allow". Undeclared is the dangerous state and must
  fail, not pass quietly.

## Scope

- [ ] Add `.github/licence-allowlist.json`. Two lists: `allowed`, the SPDX identifiers this project may ship, each
      with a one-line reason; and `denied`, the copyleft terms that would oblige the application's own source, each
      with a one-line reason. **Derive the initial contents from the bill of materials of the current `main`, not
      from memory** — run the `sbom` job's Syft invocation locally, or download the artefact from a recent green run,
      and record in the file's own `$comment` which run or command the list came from and on what date. A licence
      identifier nobody in the tree uses does not belong in the file.
- [ ] Add `scripts/licence-audit.py`, following the house pattern exactly: a module docstring saying why the check
      exists and what it will and will not catch; read the CycloneDX document; read the allowlist; classify each
      component as allowed, denied, **undeclared** or unknown; print a step-summary table of component, version,
      ecosystem and licence with the verdict; and exit non-zero naming the first failing class. Arguments:
      the document path, `--allowlist`, `--label`, `--allow-empty`, `--accepted`, `--register`, `--as-of` and
      `--self-test`.
- [ ] Decide and state, in the docstring, how a **multi-licence** component is judged (a component offering
      `MIT OR Apache-2.0` is allowed if any offered licence is allowed; a component requiring `GPL-3.0 AND MIT` is
      denied if any required licence is denied) and how an SPDX expression that cannot be parsed is treated
      (**as undeclared**, which fails). Getting this wrong is how a licence gate becomes theatre.
- [ ] Reuse the `SEC-EX-nnnn` register for the exception path: `--accepted` takes a JSON file of accepted licence
      findings in the same discriminated shape the sibling sub-issue establishes for `.github/sarif-accepted.json`
      (`kind`, and for `kind: "accepted-risk"` the `exception`, `owner` and `expires` fields), `--register` points at
      `docs/security/exceptions.md`, and an expired or unregistered entry **fails**. Do not invent a second register
      and do not invent a second date rule.
- [ ] Extend `scripts/licence-audit.py --self-test` to cover, as named sub-checks: a denied licence fails; an
      undeclared licence fails; an unparseable expression fails as undeclared; an allowed licence passes; an
      `OR`-expression with one allowed member passes; an `AND`-expression with one denied member fails; a denied
      licence covered by an in-date `accepted-risk` entry passes and is printed; and the same entry one day past its
      expiry fails.
- [ ] Wire it into the existing `sbom` job: a "Prove the licence gate still detects a forbidden licence" step running
      `--self-test`, then the gate step, both `if: ${{ !cancelled() }}`, and the gate step additionally gated on the
      document having been produced — matching the job's existing `steps.document.outcome` pattern rather than
      inventing a new condition. Pin nothing new: both steps are `run:` lines calling Python 3.
- [ ] Update `docs/process/release-gates.md` `RG-08`'s detail section so its "What it checks" row names
      `.github/licence-allowlist.json` and `scripts/licence-audit.py` instead of promising them, and
      `docs/nfr/traceability.md` `NFR-SE-07` so its verification column names the licence gate.
- [ ] Versioned configuration (DOR-11): the allowlist is **versioned configuration in the repository** — not code,
      not a database row, not an environment variable. The file says so in its `$comment`, and says that widening it
      needs a reason line and a reviewer, because `.github/CODEOWNERS` is what enforces that.

## Acceptance criteria

- [ ] `python3 scripts/licence-audit.py --self-test` passes and covers every named sub-check in **Scope** above.
- [ ] **The gate runs green against the bill of materials of the current `main`.** This is the real test of whether
      the allowlist was derived from the tree or from memory, and the pull request pastes the component table.
- [ ] Every component in the current bill of materials is classified; the count of classified components equals the
      count of components in the document, pasted as two numbers. A component the script silently skipped is the
      failure mode this criterion exists to catch.
- [ ] **Negative case, the gate gates in CI, not only in the self-test**: one deliberately broken branch adds a
      component with a denied licence to a lock file, the `sbom` job fails at the gate step with a readable message
      naming the component and the licence, the run is linked in the pull request and the branch is deleted. This is
      the `docs/process/workflow-demo.md` pattern.
- [ ] **Negative case, undeclared is not allowed**: a component with no licence metadata fails, and the message says
      so in those words rather than reporting it as an unknown licence.
- [ ] **Negative case, no silent pass**: a missing or unreadable bill of materials does **not** make the gate green.
      The job fails, or it passes only under an explicit `--allow-empty` with a visible warning step; whichever is
      chosen is stated in the script's docstring and in the job, and the pull request shows the behaviour by deleting
      the document before the gate step on a scratch run.
- [ ] **Exception case**: the exception path is bounded and reuses the sibling's register — a denied licence may be
      carried only by an in-date `kind: "accepted-risk"` entry naming a `SEC-EX-nnnn` row, an approver and an expiry,
      and the entry is printed in the summary with its days remaining. It cannot be renewed by editing the date; a
      renewal is a new identifier. Widening `allowed` instead is explicitly **not** the exception path, and the
      allowlist's `$comment` says so.
- [ ] **No invented number**: no severity, waiver duration or remediation window is written here. `RG-08`'s S1
      classification and `docs/nfr/security-operations-targets.md` section 2.1's windows are cited as they stand.
- [ ] `./scripts/dev docs` passes; `dotnet format --verify-no-changes` is clean; every test tier that ran before
      still runs and is green. No `.cs` file is touched.

## Migration and rollback

No table, no column, no migration; `dotnet run --project src/Tools/Tailor360.Cli -- migrate --dry-run` reports no
outstanding change.

Rollback is a revert, and it is the dangerous direction: reverting removes the gate, so the build goes **green**
rather than red, and a coverage loss is invisible. The pull request therefore carries the deliberately-broken-branch
run as proof the gate bites, and `RG-08`'s detail row states that removing the gate is a change to the release-gate
catalogue, not a configuration tweak. A licence failure on `main` caused by a new transitive dependency is handled
as the allowlist says: upgrade, remove, or write a dated `SEC-EX-nnnn` exception — never by widening `allowed`
without a reason line and a reviewer.
