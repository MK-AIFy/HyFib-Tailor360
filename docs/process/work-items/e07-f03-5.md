## Acceptance criteria

- [ ] With `Custody:GateEnabled = true` and a garment whose custody is consistent and has no open case, the
      `CustodyReconciled` predicate of the existing ready gate is **satisfied** and the job can reach ready —
      proved through Orders' own recomputation path, with no change to Orders' source.
- [ ] **Negative — fails closed.** With the gate on and an **open reconciliation case**, the predicate blocks and
      the block names the case reference; with the gate on and no `job_custody_state` row, the answer is `Unknown`
      and the predicate still blocks (INV-CDY-05's fail-closed discipline applied to the ready gate, per note 3).
- [ ] A Tailor Master reads a job's timeline over HTTP and sees, in server-time order, the intake scan, a transfer
      out, a receive, a refused mismatch scan, the case it opened and the correction that resolved it — **with the
      correction beside the event it corrects**.
- [ ] **Negative — other branch.** A timeline or search request for a job whose `current_custody_branch_id` is
      another branch answers exactly as a job that does not exist; a foreign `{garmentJobId}` gets the same answer
      (`matrix.yaml` `identifier-editing`).
- [ ] **Negative — no personal data.** A contract test asserts the timeline payload and the search payload carry
      no customer name, no phone number, no measurement and no media URL — the same assertion the resolve endpoint
      carries (`barcode-handoff.md` section 5: "The resolve endpoint returns no contact fields at all, which is
      covered by a contract test"). There is no `ITimelineSource` entry to assert over, for the reason in **Scope**.
- [ ] **Exception — a withdrawn case.** A withdrawn case appears on the timeline as withdrawn and does **not**
      make the answer `NotReconciled`; nothing is deleted to achieve that.
- [ ] Both routes declare one permission, one rate-limit policy and a resource scope or a recorded justification
      (ARCH-007, ARCH-017, ARCH-023); neither is audited, because neither is a state change and neither reads
      personal data (`CLAUDE.md` section 4 rule 5).
