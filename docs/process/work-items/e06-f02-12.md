Sub-issue of #33. E06-F02-2 and E06-F02-3 publish the whole workflow administration API and no screen reaches it:
`clients/pwa/src/admin/adminDestinations.ts` (32 lines) lists eight destinations and none is workflows,
`clients/pwa/src/admin/adminPermissions.ts` names ten keys and neither `catalog.workflows.edit` nor
`catalog.workflows.publish` is among them, and `clients/pwa/src/app/router.tsx` has no `/admin/workflows` entry. Plan
Section 8 (#33) describes what is missing precisely: an "editor with phase list, transition matrix and graph preview
highlighting unreachable phases, dead ends, missing start/end and phases with no eligible role; publish refused while
validation reports errors".

**This slice is the list, the client module and the read-only version view; the editor is E06-F02-12b.** The split is
forced by the measured precedent in this tree, not by preference:
`clients/pwa/src/routes/catalog/CatalogVersionEditorRoute.tsx` is **994 production lines for one route** (and
`CatalogDesignRoute.tsx` is 1,269), while its list route is 211 and its API module 294. The template editor is the same
story: `TemplateVersionEditorRoute.tsx` is 848 lines before `TemplateFieldForm.tsx` (523) and `TemplateRuleBuilder.tsx`
(330). A phase list, a keyboard-reachable transition matrix, a graph preview, a findings report and a publish dialog in
one pull request with a list route and an eight-route API module would have been 1,800 lines or more — two sessions
presented as one.
