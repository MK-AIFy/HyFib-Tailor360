## Acceptance criteria

- [ ] Prometheus loads every rule file with no parse error and no rule in `err` state, and Alertmanager loads its
      configuration, both verified with the vendor config-check commands against the compose profile.
- [ ] A synthetic burn — errors injected at a rate above 14.4× budget consumption — fires **Fast burn** within its short
      window, and the firing alert carries a `severity`, a plain-language `summary` and a `runbook_url` that opens a
      runbook that exists. This is the "alert test" that `docs/nfr/traceability.md` rows NFR-OP-02 and NFR-OP-03 ask for
      as evidence.
- [ ] The Alertmanager watchdog fires continuously while Alertmanager is up and **stops** when Alertmanager is
      stopped, which is what the dead-man's switch detects. (Stopping the **worker** and firing the heartbeat rule is
      child 5b's criterion, against the same NFR-BG-08 row.)
- [ ] **Negative:** a `4xx`-only load — authorisation refusals, idempotency conflicts, `426` outdated client — burns
      **no** error budget and fires nothing, because `docs/nfr/slo.md` section 3 excludes them from the SLI. An alert
      that fires here is a false page, and a false page is what kills an alerting system.
- [ ] **Negative:** the conformance test fails on a rule with no `runbook_url` and on a `runbook_url` naming a file that
      does not exist, proved by negative controls. "An alert with no runbook is a defect in the alert" is enforced
      mechanically, not by review.
- [ ] **Exception — the silence case:** when the exporter stops, the `absent()` companion rules fire rather than every
      dashboard going green; and when Alertmanager is configured with no real receiver (the **OD-15** default below),
      the rules still evaluate and fire, and the firing is visible in Alertmanager's own user interface, so the work is
      verifiable before the decision is taken.

rollback of this change is itself a P2 condition until it is re-applied.
