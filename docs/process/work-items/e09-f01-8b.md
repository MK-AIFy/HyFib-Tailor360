## Acceptance criteria

- [ ] An Owner opens the preview from a draft version, prices a line with a surcharge and a discount naming one of
      that version's rules at a value inside the counter's bound, and sees the base, the surcharge, the discount, the
      gross, the taxable value, the tax components and the document total — together with the price-list version, the
      tax configuration version and the GST registration the calculation used, and `calculatedAt`.
- [ ] Pricing the same line against an **inter-state** place of supply shows `InterState` and a single integrated-tax
      component, never CGST and SGST as well; pricing it intra-state shows the pair and no integrated tax.
- [ ] A case shape is pressed, the form fills, the preview runs, and the screen shows **which shape was run** — so
      the accountant's examples can be walked through in front of the accountant before a publish.
- [ ] The document `roundOff` is shown as its own line, not folded into the total, so the reconciliation between line
      components and document totals is visible rather than only asserted in a test (the parent's acceptance
      criterion 4).
- [ ] **Negative, the unauthorised override — the parent's criterion 3:** a caller holding
      `billing.manage_price_lists` but not `billing.override_price` sends an override beyond the version's threshold
      and is refused with `billing.approval-required` rendered against the `override.rate` field as a sentence naming
      who may authorise it; a discount beyond its rule's hard maximum is refused with
      `billing.discount-above-maximum` against `discount.value`. Nothing is priced, the screen does not retry behind
      the person's back, and it does **not** explain the refusal by comparing the variance percentage it was shown
      against the threshold — that comparison is made unrounded server-side (`PricingEngine.cs` line 171) and a
      client-side restatement of it would sometimes contradict the server.
- [ ] **Negative, missing configuration:** a branch with no GST registration in force on the chosen date, or a
      version pricing no branch, answers `billing.configuration-missing`; the screen says **what** is missing and
      links to the screen that records it — `/admin/gst-registrations` from E09-F01-4, or the version's conventions
      form from E09-F01-6 — both of which exist by the time this merges.
- [ ] **Negative, a rule the version does not carry:** a discount naming an unknown rule code answers
      `billing.discount-rule-not-found` and a retired one `billing.discount-rule-not-in-force`, each against the
      line it was on, identified by the caller's own `lineKey`.
- [ ] **Negative, a duplicated line key:** two lines sharing a key answer `billing.line-key-duplicated`; the screen
      mints a distinct key per line itself so a person cannot cause this by accident, and still renders the refusal.
- [ ] **Exception path:** an override **within** the threshold is priced and needs a reason, not a permission, and
      the line reports `approvalExercised` as false with its variance — so the screen distinguishes "allowed with a
      reason" from "needs authorisation", which is the distinction the engine makes at `PricingEngine.cs` line 171.
- [ ] **Negative, authorisation:** a caller without `billing.manage_price_lists` meets `RequirePermission`'s
      `EmptyState`, never a redirect, and the destination is absent from the administration navigation. The test also
      asserts the screen handles the **server's** refusal, because the claim list can be stale.
- [ ] **Offline:** the preview control renders `OfflineBlockedAction` — "Needs connection — this will not be
      queued", word for word. A preview is an audited `POST` and billing work is never queued.
- [ ] **Every figure on screen is one the server sent**: no total, tax, variance or round-off is computed in the
      client, and the test asserts the rendered strings are exactly what the stub returned.
