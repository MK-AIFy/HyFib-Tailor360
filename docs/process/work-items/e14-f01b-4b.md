Sub-issue of #56. The W5 half of this parent owes an "automated security regression suite" over eleven abuse-case
families (plan Section 8), split across seven sibling sub-issues. **This sub-issue takes one family, and it is the only
one in the catalogue that may not be testable at all: `ABF-09` server-side request forgery.** It is on its own because
it is not a test-writing problem, it is a **finding** problem — and the parent's second acceptance criterion ("no
critical/high release-blocking finding remains unresolved") is what it exercises.

**The control does not exist.** `src/Platform/Tailor360.Platform.Abstractions/Ports/IOutboundHttp.cs` declares the
port; ARCH-016 forbids constructing an `HttpClient` directly and `tests/Tailor360.ArchitectureTests/SourceConventionTests.cs`
enforces that; and `grep -rl IOutboundHttp src/` returns **exactly two paths** — the port file itself and
`src/Modules/CLAUDE.md`. There is no implementation. `docs/nfr/traceability.md` `NFR-SE-10` states the behaviour it
must have — refuse private, loopback, link-local and metadata addresses, disable redirects, cap response size — with
"Proof scheduled (#54, #55)".

So the honest outcome of this sub-issue may be a **blocking finding with an owner, an expiry and a corrective issue**
rather than a green suite, and it is written to make that outcome cheap and visible instead of letting a session write
a test that passes because it tested nothing. That is why it depends on the exception register as well as on the
models.
