Sub-issue of #56. The W5 half of this parent owes an "automated security regression suite" over eleven abuse-case
families (plan Section 8), split across seven sibling sub-issues. **This sub-issue takes the last two: `ABF-10`
credential abuse and `ABF-11` denial of service.** They belong together and apart from the other five: both extend
machinery that is **already substantial and already merged** — nineteen Identity integration test files, nineteen
Identity unit test files, the complete eight-policy rate-limit catalogue — and **neither depends on a single unmerged
feature issue**. That makes this the one suite in the W5 half that can be taken the day the shared machinery lands,
which is worth saying plainly because the other five all wait on a W3, W4 or W5 surface that does not exist yet.

What is missing in both is the same thing: the repository proves **declarations** and **single requests**, and proves
nothing about **sequences** or **effects**. ARCH-017 proves every endpoint declares a rate-limit policy; nothing
exhausts a limiter and checks that it refuses. `tests/Tailor360.IntegrationTests/Identity/` proves each credential
endpoint behaves; nothing composes them into an attacker's run across many accounts.

## What is missing

- No **sequence** across accounts: a stuffing run from rotating addresses, throttled per account as well as per
  address. The existing throttle tests prove the policy, not the composition.
- Enumeration is proved impossible on **sign-in** and nowhere else: not on recovery, not on enrolment, not on the
  passkey ceremony, not on the user directory.
- The four `HalfSignedInSessionTests` cases exist separately; nothing composes them into the single story "a
  half-signed-in session cannot finish the job another factor was meant to gate".
- **No test asserts a rate-limit policy does anything.** ARCH-017 proves the declaration; nothing exhausts a limiter,
  checks the `Retry-After` a client can obey, or checks that the partition is the one intended.
- Nothing tests resource exhaustion beyond one request: an unbounded page size, an oversized body read into memory, a
  worker lease held for ever, a dead-letter queue that grows without bound.

      documented route and the recovery does **not** also clear the second factor; a caller that waits out

      everything.
- [ ] **No limit, cap, window or propagation target is invented**: each is cited from

- [ ] The pull request reports the integration tier's duration before and after against the 15-minute pull-request
