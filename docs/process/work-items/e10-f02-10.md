Sub-issue of #45. **Evidence child. Writing the script is a session; running it is not — it needs an Owner, a Branch
Manager and a Tailor Master at a keyboard, and no coding child of #45 is blocked on it.** The parent's required
verification ends with "ops UAT scenarios (overdue, hold, QC fail, reassignment)", and `docs/process/` holds exactly
one user-acceptance script today, `uat-administration.md`. This child writes
`docs/process/uat-operational-analytics.md` to that shape, marked **written and not yet run**, and then records the run
when the shop's people are available. The two halves are deliberately one issue because a script nobody ever runs is
not evidence, and a run with no script is not repeatable.

## What is already built (do not re-build)

- `docs/process/uat-administration.md` — **the shape this script follows, section for section**: a status block that
  says "Written and not yet run", who runs it, the prerequisite, the evidence expected per step (a screenshot of what
  the person saw, and for every refusal the RFC 9457 body with its correlation identifier), and which parts are run as
  which role. `docs/process/` also holds `release-evidence.md`, `release-gates.md`, `definition-of-done.md` and
  `waivers.md`; read `waivers.md` and note that it is **not** where "the owner has not run this yet" belongs.
- `docs/security/role-walkthrough.md` — the scripted per-role walkthrough, whose own status note in
  `docs/security/README.md` line 38 reads "**Written 2026-09-06. Section 3 run 2026-09-06 and its results recorded**;
  sections 4 to 6 are not run". That is the honest shape of a half-run script, and this one copies it.
- `scripts/dev` — `doctor`, `up`, `run`, `reset`, `status`, `docs`. **`reset` is destructive and refuses in
  Production**; it runs compose `down -v`, then `migrate`, `init-reference-data`, `seed-synthetic`.
- **What `reset` actually leaves you with, verified by reading the command rather than assuming.**
  `src/Tools/Tailor360.Cli/Commands/SeedSyntheticCommand.cs` upserts **two Identity branches and two feature flags**
  and nothing else. Its own output says: "One representative user per role in each branch is created by the
  administration screens of issue **#25**" and "Customers, catalogue, orders and billing fixtures are added by their
  own issues and consolidated into the shared fixture library by issue **#61a**". So after `./scripts/dev reset` there
  are **no users, no customers, no orders, no garment jobs and no QC data at all**. `init-reference-data` adds the
  organisation, the catalogue, design, measurement and related reference rows.
- **There is no first-owner bootstrap command.** `docs/architecture/deployment.md` line 75 and ADR-0010 both list
  `create-owner` among the command-line tool's verbs, but `src/Tools/Tailor360.Cli/Commands/` holds only
  `FlagsCommand.cs`, `InitReferenceDataCommand.cs`, `MigrateCommand.cs`, `ReplayOutboxCommand.cs` and
  `SeedSyntheticCommand.cs`, and `grep -rn "create-owner\|CreateOwner" src/ scripts/` returns nothing. The script must
  therefore say how the first signed-in Owner is obtained rather than citing a command that does not exist — and if it
  still does not exist when the run is attempted, that is a finding recorded against #25 and the run is deferred, not
  faked.
- `tests/e2e` and `playwright.config` **do not exist** and arrive with **#52** (`scripts/dev` line 434 says so in as
  many words), so this is a manual procedure and not an automated suite. `tests/load` does not exist either, and
  `docs/evidence/` does not exist — the evidence lives with the pull request and with
  `docs/process/release-evidence.md`.

## Scope

- [ ] **`docs/process/uat-operational-analytics.md`**, modelled section for section on `uat-administration.md`, with a
      status block marked **written and not yet run** and the date it was written.
- [ ] **Four journeys, which are the parent's own**, each as numbered steps naming the screen, the role that runs it,
      what the person should see, and the evidence to capture:
      1. **Overdue** — a garment past its promised date appears in the overdue count on the pipeline dashboard and in
         the drill list, and the Today tile agrees with the dashboard.
      2. **Hold** — a garment put on hold appears in the on-hold count, and its held time shows as **excluded from
         turnaround** rather than as lateness, which is the treatment the metric dictionary records as proposed.
      3. **QC failure** — a failed QC appears on the quality dashboard with its reason code, its rework cycle and its
         denominator, and **no tailor is named anywhere on that screen**.
      4. **Reassignment** — moving open work between two tailors moves the open phases to the second and **leaves the
         earlier completions with the first**, read off the workload screen.
- [ ] **A refusal in every journey**, because the deny path is what a UAT most often skips: a Cashier following the
      **Reports** destination meets the forbidden state (they hold no Reporting permission at all — `SystemRoles.cs`
      lines 351 to 373); an Auditor on the workload screen sees the throughput columns **absent with an explanation**
      and not blank; a caller asking for another branch sees only their own branches with the covered set stated. For
      every refusal the evidence is the RFC 9457 body with its correlation identifier, exactly as
      `uat-administration.md` requires.
- [ ] **An honest prerequisites section**, which is the part most likely to be got wrong. It states: `./scripts/dev
      doctor` and `./scripts/dev reset` give two branches, reference data and two feature flags and **nothing else**;
      the per-role users come from **#25**'s administration screens; the orders, phases, assignments, QC results and
      reworks come from the screens of **#204**, **#33** and **#34**, or — where a screen does not exist yet — from the
      documented event-publishing harness (`tests/Tailor360.IntegrationTests/Billing/InvoiceScenes.cs`'s
      `PublishAsync`/`DispatchAsync` shape, and E10-F02-1's `ReportingScenes.cs`), named as a development-only route
      with its limitation stated; and the first signed-in Owner is obtained as described above, with the missing
      `create-owner` command recorded as a gap.
- [ ] **Synthetic data only, in every step and every screenshot** (CLAUDE.md section 4 rule 10), with the rule written
      into the script so a later runner cannot reasonably use a real customer or a real member of staff.
- [ ] **`./scripts/dev docs` green**, so every relative link in the new document resolves.
- [ ] **The run, and its record.** When the three people are available, run the script, fill in its results table,
      record the date, attach the screenshots and the refusal bodies, and raise a new issue linked to #45 for each
      defect found. If the run cannot happen before #45's wave exit gate, the document stays "written and not yet run",
      **that status is reported at the gate as a finding**, and it is **not** written up as a waiver —
      `docs/process/waivers.md` is for a gate that cannot be met, not for an approval or an appointment nobody has yet
      arranged.
