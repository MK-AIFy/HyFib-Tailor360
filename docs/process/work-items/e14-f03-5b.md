## What is missing

No rule watches any background signal, so child 1's gauges are collected, drawn on child 4b's dashboard and alerted on
by nobody — and **NFR-BG-01** and **NFR-BG-08** have no artefact. No `absent()` rule exists anywhere, so a stopped
exporter makes every background panel go quiet and every background rule go green at the same time, which is the failure
mode that makes an alerting system worse than none. No business-integrity rule exists, so a signal whose producer has
not shipped is indistinguishable from a signal that is healthy.

## Acceptance criteria

- [ ] Prometheus loads both new rule files with no parse error and no rule in `err` state, and the conformance test with
      its four negative controls is green.
- [ ] **Stopping the worker fires the heartbeat rule inside twice `WorkerOptions.HeartbeatInterval`** — the NFR-BG-08
      criterion — with a `severity`, a plain-language `summary` and a `runbook_url` that opens the worker-stopped
      runbook.
- [ ] Filling an outbox with undispatched messages fires the outbox-lag rule at the S7 threshold and **per module**, so
      the firing alert names which module is behind rather than "the outbox".
- [ ] **Negative — the silence case, which is the point of this issue:** stop the exporter and the `absent()` companions
      fire while **no** background rule goes green and **no** background panel shows a healthy value. A test that only
      proves the positive direction would pass on a system that had stopped measuring.
- [ ] **Negative:** a business-integrity rule whose producer does not exist fires as **"no producer — owned by #NN"**
      and **not** as a breach, so an unbuilt module is never reported as a data-integrity incident. A rule that fires
      the wrong way here would wake somebody for a module that has not been written.
- [ ] **Negative:** a healthy, idle system fires nothing at all over a quiet 30 minutes — no outbox rule on an empty
      outbox (child 1's gauge reports zero, not absent, which is what makes this possible), no dead-letter rule on zero
      dead letters, no job-lease rule on a job that has not run. A false page is what kills an alerting system.
- [ ] **Exception:** the audit-chain-stalled rule is **P1** and its runbook's first step is evidence preservation, not
      repair; the rule's `summary` carries **no** hash, **no** chain-head value and **no** actor — only the age and the
      escalation. `docs/nfr/data-classification.md` section 8 is why.

## Migration and rollback

No database change; `migrate --dry-run` output proves it. Rollback is reverting the commit and reloading Prometheus,
which reads from disk. A bad rule cannot affect a request: nothing in `src/` reads these files. The one operational
hazard is the reverse — reverting leaves the background work **unmonitored**, so the pull request states that rollback
of this change is itself a P2 condition until it is re-applied.
