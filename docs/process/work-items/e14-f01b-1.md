## What is already built (do not re-build)

- `src/Hosts/Tailor360.Web/Middleware/SecurityHeadersMiddleware.cs` — the whole header set, with a long docstring
  that is the design record: a per-response 128-bit nonce published to `HttpContext.Items` under `NonceItemKey`;
  `PolicyFor(nonce)` returning `script-src 'nonce-…' 'strict-dynamic'` plus the `StaticDirectives` constant
  (`default-src 'self'`, `base-uri 'none'`, `style-src 'self'`, `img-src 'self' data: blob:`,
  `media-src 'self' blob:`, `font-src 'self'`, `connect-src 'self'`, `worker-src 'self' blob:`,
  `manifest-src 'self'`, `object-src 'none'`, `frame-src 'none'`, `form-action 'self'`, `frame-ancestors 'none'`,
  `upgrade-insecure-requests`); and the headers written in an `OnStarting` callback so
  `UseExceptionHandler`'s `Response.Clear()` cannot discard them — `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin`,
  `Cross-Origin-Resource-Policy: same-origin`, `Permissions-Policy: camera=(self), microphone=(), geolocation=(),
  payment=()`. **Read the docstring before editing: it explains why `'strict-dynamic'` rather than `'self'`, and why
  the headers are written on starting.**
- `src/Hosts/Tailor360.Web/Endpoints/AppShellEndpoints.cs` — the shell renderer, which stamps the response's nonce on
  the module script and the `modulepreload` links, refuses to render without a nonce, and is never cached. Its
  docstring explains why the preloads are stamped. `NoncedTagCount` makes the stamping testable.
- `clients/pwa/index.html` — one `<script type="module" src="/src/main.tsx">`, no inline script, no inline style
  attribute.
- `clients/pwa/src/design-system/foundations/setCssVariable.ts` (with `setCssVariable.test.ts`) — the sanctioned way
  to set a custom property at run time, writing through the CSSOM rather than serialising a `style` attribute,
  because `style-src` has no `'unsafe-inline'`. Used by `components/primitives/Button.tsx`,
  `components/layout/AppShell.tsx`, `components/dialogs/UndoBar.tsx` and
  `design-system/foundations/tokens.stories.tsx`.
- `tests/Tailor360.IntegrationTests/Security/ContentSecurityPolicyTests.cs` — the existing suite, with
  `ThePolicyContainsNoUnsafeSource`, `ScriptsAreAdmittedByNonceRatherThanByOrigin`, a `[Theory]`
  `TheRemainingDirectivesAreClosed(string directive, string expected)`, `ThePolicyIsEnforcedAndNotReportOnly`,
  `TheShellCarriesTheResponsesOwnNonceOnEveryScript`, `ABuiltShellIsStampedOnItsEntryModuleAndItsPreloads`,
  `TheShellParserFindsEveryScriptAndPreload` and `AStylesheetOrFontLinkIsNotStamped`. **Extend this file — the
  `[Theory]` is the natural home for two new directives.**
- `tests/Tailor360.IntegrationTests/Security/CrossSiteDefenceTests.cs`, `ErrorLeakTests.cs`,
  `ForwardedHeaderTests.cs` — the anti-forgery, origin, `Sec-Fetch-Site` and error-leak suites.
- The validation and problem-details plumbing, which is **distributed by design, not central**:
  `src/Platform/Tailor360.Platform.Security/Antiforgery/SecurityProblemDetails.cs`,
  `Authorisation/AuthorisationProblemResultHandler.cs`, `Endpoints/RequestSafetyEndpointExtensions.cs`, the
  per-module `Problems.cs` (for example `src/Modules/Billing/Tailor360.Modules.Billing.Api/Problems.cs`), and
  `src/Hosts/Tailor360.Web/OpenApi/ApiProblemResponses.cs`. The contract tier already holds
  `EndpointPayloadTests.cs`, `EndpointPolicyTests.cs`, `EndpointRequestSafetyTests.cs`,
  `EndpointRateLimitTests.cs`, `EndpointResourceScopeTests.cs`, `ResponseViewPayloadTests.cs`,
  `OpenApiDocumentTests.cs` and `OpenApiLint.cs`. **The review writes down what these already prove; it does not
  rebuild them.**
- `docs/api/conventions.md` — sections 3 (Requests) and 4 (Responses), including the RFC 9457 envelope and the field
  error shape. This is where the validation and encoding review is recorded, because this document already owns the
  subject.
- `docs/nfr/support-matrix.md` — the browser floor. The middleware docstring already reasons from it ("the oldest of
  them is Safari 16.4"), and the Trusted Types decision must reason from it too: Trusted Types is **not** supported
  by Safari or Firefox at the time of writing, which is exactly why the directive is additive rather than
  load-bearing.
- `clients/pwa/CLAUDE.md` and `clients/pwa/eslint.config.*` — the client rules and the lint configuration a new
  restriction is added to.

## What is missing

- No Trusted Types directive, so a DOM cross-site-scripting sink reached through a library or a future component is
  unconstrained in the browsers that would enforce it.
- No lint rule forbidding the sinks: `grep -rn "dangerouslySetInnerHTML" clients/pwa/src` returns nothing, and
  `innerHTML` appears in exactly **two** files at **four** sites — `components/dialogs/focusable.test.ts:6` and
  `design-system/testing/expectNoHorizontalOverflow.test.ts:200`, `:232`, `:246`. `outerHTML`,
  `insertAdjacentHTML` and `document.write` appear nowhere. So the tree is clean **today** and nothing keeps it
  clean tomorrow.
- `Cross-Origin-Embedder-Policy` is absent while its two neighbours are present, and nothing records whether that is
  a decision or an omission.
- No written review of where validation and output encoding happen, so `ASVS` chapter V5 has no evidence row and a
  reviewer has to re-derive the answer from eight test files.
