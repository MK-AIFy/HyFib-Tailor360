Sub-issue of #51. #E12-F02-3a built the encrypted device store and nothing uses it. This sub-issue gives it its first
and, for this release, its only consumer: the measurement capture wizard of #28, which is the single form plan
Section 6.2 note 8 approves for local drafts ("#28 and #32 use server-side drafts only; … **#51 is the only
implementation of encrypted local drafts**"). The deliverable is small and entirely visible: an adapter, a debounced
autosave, and a **restore notice** that asks before it puts somebody's half-typed measurements back on the screen.

**Why the notice matters more than the autosave.** A silent restore of stale measurements is how the wrong body
measurement reaches a garment. The wizard already announces "Saving…", "Saved" and "Not saved — retrying" into the
shell's autosave channel, whose own comment cites **A11Y-44**: "A draft that saves silently is indistinguishable from
one that does not save at all." A restore is the same problem pointing the other way, and the answer is the same: say
it, in a region that stays on the screen.

## What is missing

- Nothing reads or writes the device store. `grep -rn "deviceStore" clients/pwa/src` finds only #E12-F02-3a's own
  files and its guard test.
- The wizard loses everything typed since the last successful `saveGroup` if the tab closes, the device sleeps, or
  the link drops mid-step.

## Scope

- [ ] **`clients/pwa/src/measurements/localDraft.ts`** — the adapter, and the only place the wizard meets the store.
      `saveLocalDraft`, `readLocalDraft` and `discardLocalDraft` over
      `{ measurementDraftId, customerId, templateVersionId, state, unit, stepId, dirty, tag }`, keyed by the **server**
      draft identifier, purpose `measurement-draft`, binding from `bindingFor(user)`. `readLocalDraft` returns a
      discriminated result — `{ status: 'none' }`, `{ status: 'kept', record, writtenAt }`, `{ status: 'unavailable' }`
      — so the caller never has to interpret a thrown error, and an unavailable store is indistinguishable from no
      draft as far as the screen is concerned.
- [ ] **Write points in the wizard.** After a change, **debounced** (500 ms, a number this issue is free to choose
      because it is a rendering detail with no product meaning — say so in the comment so a reviewer does not look for
      a source), and after every successful `saveGroup` so the local copy never claims to be ahead of the server.
- [ ] **Discard points.** On a successful confirmation, and on the `closed` path for both `'expired'` and
      `'confirmed'` (line 328). A local draft for a server draft that no longer exists is the one record that could
      outlive its meaning.
- [ ] **The restore notice.** On mount, when `readLocalDraft` returns `kept` for the server draft being opened, show a
      notice **above the step** — "We kept what you typed on this device", with the time it was kept, and two actions:
      *Use it* and *Discard*. Never restore silently. Announce the notice through `status.announceAutosave`, not a
      toast (**A11Y-42**, **A11Y-44**). The time is formatted through `getFormatters` from
      `clients/pwa/src/i18n/formatters.ts` (`DEFAULT_TIME_ZONE = 'Asia/Kolkata'`), never a direct `Intl` call.
- [ ] **The quota sentence.** When a write rejects and `isQuotaExceeded(error)` is true, show the person a plain
      sentence from `clients/pwa/src/i18n/messages/offline.ts` saying their work is **not** being kept on this device
      and that they should save the step while they have a connection. The wizard keeps every typed value on screen
      and the server save path is untouched. It must never look as though the work was kept. Any other store failure
      is silent: the wizard is fully usable without the device store, and a storage error a person cannot act on is
      noise.
- [ ] **Message ids** for the notice, its two actions and the kept-at time in
      `clients/pwa/src/i18n/messages/measurements.ts`, in **both** languages, untranslated Tamil carrying the
      English text and the `// not translated — awaiting native-speaker review` comment as the rules at the top of
      `clients/pwa/src/i18n/messages/shell.ts` require. Nothing is built by string concatenation: word order differs
      in Tamil, and the kept-at sentence takes the formatted time as an ICU argument.
- [ ] **Stories** beside the existing ones in
      `clients/pwa/src/routes/measurements/measurementScreens.stories.tsx`: a **kept-work** story, a
      **storage-full** story, and the **pseudo-locale** variant of the notice
      (`clients/pwa/src/i18n/pseudo.ts`, `PSEUDO_LOCALE = 'en-XA'`, `PSEUDO_GROWTH_FACTOR = 1.4`). Use the file's own
      `link()` helper for any story that needs the offline link state, and leave every other story online. Offline
      stories **are** expected here: the deliberate absence recorded in
      `clients/pwa/src/routes/catalog/catalogScreens.stories.tsx` ("Why there is no offline story") is about
      administration screens, and this is a shop-floor screen that the file already has offline stories for.

## Acceptance criteria

- [ ] A measurer types two groups of a measurement draft, the tab is closed or the device sleeps, and reopening the
      same draft offers the kept work; taking it restores every value, the chosen display unit and the step they were
      on, and discarding it leaves the server draft untouched.
- [ ] **Negative — nothing is restored without being asked:** with a kept record present, the values on screen before
      the person chooses are the server's, not the device's. A test asserts a field's value before *Use it* is taken.
- [ ] **Negative — sign-out:** after `signOut()`, reopening the same draft as a second person offers nothing. This is
      #E12-F02-3a's shred, re-asserted here through the real route, because it is the route-level behaviour a shared
      counter device depends on.
- [ ] **Negative — another user or another branch:** a record whose binding does not match is never offered. Drafts
      are simply absent rather than listed as unavailable — a measurement draft belonging to somebody else has no
      value to this person, which is deliberately different from a queued scan (#E12-F02-4 shows those, because they
      do).
- [ ] **Negative — expiry:** a record written more than `OFFLINE_BOUNDS.maximumAgeHours` ago produces no restore
      notice.
- [ ] **Negative — the local copy never leads the server:** after a successful `saveGroup`, the kept record matches
      what was saved. A test asserts the stored `tag` equals the tag the save answered with.
- [ ] **Exception — storage full:** a write that raises `QuotaExceededError` shows the plain "not being kept" sentence,
      every typed value stays on screen, the server save path still works, and no restore notice is ever shown for
      that draft afterwards.
- [ ] **Exception — the store is unavailable:** with `indexedDB` or `crypto.subtle` absent, the wizard behaves exactly
      as it does today. No notice, no error, nothing logged, and the existing tests still pass unchanged.
- [ ] Accessibility: `expectNoAccessibilityViolations` from `clients/pwa/src/design-system/testing/axe.ts` on the
      wizard with the notice present; `clients/pwa/src/design-system/testing/expectNoHorizontalOverflow.ts` **at its
      own defaults** (320, 360, 768, 1024 and 1280 px at 100% and 200% zoom — do not narrow the list); the notice is
      announced through the autosave region and never as a toast; status carried by icon and words, never colour
      alone.

## Data and classification

| Item | Class | Purpose | Retention | Who may read it | Logs, telemetry, export |
| --- | --- | --- | --- | --- | --- |
| Local measurement draft — canonical millimetres, counts, choices, acknowledgements, the display unit, the step, the server draft and customer identifiers | **Sensitive Personal** — `docs/nfr/data-classification.md` section 5.4 covers measurement drafts explicitly | Not lose a half-measured garment to a closed tab or a dead link | **24 hours** on the device (SM-07's proposed age, the only number with a source), and destroyed earlier by sign-out, confirmation or discard. The authoritative draft and its own expiry stay server-side (#28) | Only the signed-in user whose binding matches, on that device | **Never** in a log, a problem detail, a trace attribute, a metric label or client telemetry — section 5.4 says no measurement value may appear in any of them. Never in an export |
| The kept-at time rendered in the notice | Internal | Let a person judge whether the kept work is still the work they were doing | In memory while the notice is on screen | The signed-in user | Never logged. Formatted through `getFormatters`, never a direct `Intl` call |
| The "not being kept" and "storage full" sentences | Public — message catalogue text | Tell the truth about what the device is doing | In the repository | Anyone | They name no draft, no customer and no measurement |

Nothing new is stored that #E12-F02-3a did not already classify; this issue adds the **first plaintext**, which is why
the store was designed to Sensitive Personal from the start rather than to the class of whatever arrived first.
