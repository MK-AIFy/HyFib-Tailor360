## Scope

- [ ] **`GET /api/v1/reporting/pipeline`** — work in progress grouped by branch, category and phase, with the due
      buckets (due today, due within the configured horizon, overdue), the on-hold count and the totals; `asOf`
      defaults to now and the response states it; `filter[state]=active|closed` distinguishes live work from
      historical work (the parent's sixth implementation step).
- [ ] **`GET /api/v1/reporting/pipeline/jobs`** — the drill list behind any cell of the summary, cursor-paged in the
      shape of `InvoiceEndpoints.ListInvoices`: garment job number, order number, category, service type, current
      phase, due date, queue age, hold state, lifecycle state. **No customer name and no amount** — neither is in
      the projection, which is why this route can be read by a Tailor Master.
- [ ] **`GET /api/v1/reporting/pipeline/bottlenecks`** — per phase per period bucket: work in progress, mean queue
      age and the 90th-percentile queue age, so "where is it piling up" is answerable over time rather than only
      now.
- [ ] **`GET /api/v1/reporting/turnaround`** — promised versus actual by category and service type per period
      bucket, with the on-time rate, and with the excluded populations reported as counts beside it (cancelled
      garments, and held time removed) rather than silently netted.
- [ ] **Payload types in the `Api` project** (ARCH-013 — no `Domain` type is ever returned), under
      `src/Modules/Reporting/Tailor360.Modules.Reporting.Api/Payloads/`.
- [ ] **Every route declares**: `RequirePermission(ReportingPermissions.Read, BranchScope.AssignedBranches)`
      (ARCH-007; a branch-scoped permission is `AssignedBranches` on a read, per
      `src/Platform/Tailor360.Platform.Abstractions/Multitenancy/BranchScope.cs`), exactly one rate-limit policy
      (ARCH-017) — `RateLimitPolicyNames.DefaultUser`, with `ExportHeavy` reserved for generation and export paths
      (#186, #46) — and `RequestTimeoutPolicies.Report`. Those are the values, decided here: do not defer the choice
      to what a sibling declared, because #184 is open and a session cannot read an unmerged convention. If #184 has
      already merged with something different, the pull request says so in one line and matches it. No `.Audited(...)`:
      these four carry no personal data, so
      the read is not itself sensitive (CLAUDE.md section 4 rule 5). The workload read that *is* sensitive is
      E10-F02-3b's.
- [ ] **Configuration, not code** (DOR-11): the due-soon horizon (plan Section 8's "due within N days
      (configurable)"), the period bucket sizes and the queue-age buckets are configuration under a
      `Reporting:Pipeline:` section with **no value invented** where no document fixes one. Concretely:
      `Reporting:Pipeline:DueSoonHorizonDays` is `int?` with **no code default at all**; when it is unset the
      due-soon bucket is **absent from the response** and the response says the horizon is unset, rather than
      falling back to a number nobody chose. Every response states the horizon it applied. The period bucket sizes
      are `Day`, `Week` and `Month` and the queue-age percentile is the 90th — both introduced here as the
      reporting convention and written into the dictionary, because no document fixes either and a percentile has
      to have a value to be computed at all.
- [ ] **One row per route in the `<!-- matrix:endpoints -->` block** of `docs/security/permission-matrix.md`, and
      the corresponding fixtures in `tests/Tailor360.IntegrationTests/Authorization/matrix.yaml`.
- [ ] **Regenerate** `docs/api/openapi.v1.json` and then `clients/pwa/src/api/schema.d.ts`

## Acceptance criteria

- [ ] A Branch Manager holding `reports.read` reads all four routes over HTTP and receives only their own assigned
      branches' figures, with the horizon and the `asOf` instant stated in each response.
- [ ] The summary and the drill list agree: the row count returned by `…/pipeline/jobs` for a given branch,
      category, phase and due bucket equals the count the summary reported for that cell, at the same `asOf`.
- [ ] `filter[state]=closed` returns cancelled and ready-and-delivered garments and no live work; `active` returns
      the complement. Neither answer mixes them, because "active versus historical" is the distinction the parent
      asks for and **SQ-01** means `delivered` is the last automatic state.
- [ ] Turnaround excludes cancelled garments from the averages and reports them as a separate count; held time is
      excluded from the actual turnaround and reported as its own figure, per the metric dictionary.
- [ ] **Rule-level:** every route added here declares a permission (ARCH-007) and exactly one rate-limit policy
      (ARCH-017); none carries a route parameter, so ARCH-023 is satisfied without a resource scope; the contract
      tier proves all three.
- [ ] **Negative — another branch:** a caller assigned to branch A asking for branch B by filter receives no
      branch-B row. Not an error: the filter is intersected with `AssignedBranches`, and the response states which
      branches it covered, so a reader can never mistake a silently narrowed answer for the whole shop.
- [ ] **Negative — no permission:** a Tailor without `reports.read` is answered `403`
      `security.forbidden`, per the `not-permitted` answer in `matrix.yaml`.
- [ ] **Negative — a malformed filter:** an unknown phase code, a reversed date range or a limit above the cap is
      answered with RFC 9457 problem details naming the field, never a stack trace and never a silently clamped
      answer for the range (the limit is clamped, as `ListInvoices` clamps it, and the response states the limit).
- [ ] **Exception — an empty shop:** a branch with no open work returns zeroed buckets and an empty drill list with
      the `asOf` instant, not a 404.
