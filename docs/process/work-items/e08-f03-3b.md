Sub-issue of #40. `E08-F03-3` makes an alert respondable and publishes `inventory.low-stock-raised.v1`,
`inventory.low-stock-cleared.v1` and `inventory.low-stock-escalated.v1`; nobody is told. This child is the
**Notifications** half and nothing else: the routing rule that turns those three events into a staff message, the
`inventory.*` staff templates, and the one metric that cannot exist without a delivery — alert-to-first-delivery
latency. It is a separate child because it is a **different module**: plan Section 6.2 note 4 allows #40 exactly two
file families inside Notifications and nothing more, and a pull request that edited Inventory's source and
Notifications' source at once would be two slices in one branch.

Checked in this working copy today: `src/Modules/Notifications/` holds **7 `.cs` files**, all scaffolding — no
`Routing/` folder, no `Templates/`, no template store, no intent table, no adapter. Every Notifications path named
below arrives with #47's children and **must be read from the tree, not from this body**.

## What is missing

- No routing for any Inventory event: the three events land in the outbox, #209's handler can raise an intent, and
  nothing decides who a **staff** alert is addressed to.
- No `inventory.*` template exists in the template key space, so even a correctly routed intent has nothing to
  render.
- No alert-to-first-delivery measurement, which is one of the four metrics #40's blueprint names.
