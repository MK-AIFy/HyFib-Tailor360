## Acceptance criteria

- [ ] An Owner opens a draft version from the versions screen, adds a `Service` item with a base rate, a unit and a
      tax code chosen from the published tax configuration, edits it, removes a second one, and reads everything
      back after a reload — no deployment, no database access.

      field was re-sent, because a field left out is refused rather than kept.
- [ ] **Negative, no tax configuration published:** the picker says so in one sentence, links to
      `/admin/tax-configuration`, and the field still accepts a typed code — the item saves, because the check is at
      publication. This is the criterion that keeps a shop from being blocked by the setup order.
- [ ] **Negative, the refused item:** a malformed unit answers `billing.unit-not-well-formed`, a malformed rate
      `billing.amount-not-well-formed`, and a duplicate item code `billing.code-not-unique` — each as a field error
      against its own field, the typed values kept, and a retry reusing the **same** `Idempotency-Key`.
- [ ] **Negative, an omitted money-bearing flag:** submitting the item form without the active choice is refused and
      the message names the field; the test asserts the request body carried no value the person did not type.
- [ ] **Negative, concurrency:** a write against a tag the screen no longer holds answers `billing.version-changed`,
      and the screen offers a re-read and a retry with the **same** `Idempotency-Key`; the tag carried into the next
      write is the one the previous response returned, **including after a `204` item removal**.
- [ ] **Negative, authorisation:** a caller without `billing.manage_price_lists` meets `RequirePermission`'s
      `EmptyState`, never a redirect; the test also asserts the screen handles the **server's** refusal of a write,
      because the claim list can be stale.
- [ ] **Exception path:** a published version offers no item control and no conventions control; the screen says a
      change is a clone into a new draft and offers that route back to E09-F01-6's versions screen. Any discount
      rules it holds are still **visible**, read-only.
- [ ] **Offline:** every write control renders `OfflineBlockedAction` — "Needs connection — this will not be
      queued", word for word.
- [ ] Every amount is rendered with `formatMoney` and every percentage with `formatPercent`; no `toLocaleString` at
      a call site, and no arithmetic on a `number | string` decimal in the client.
