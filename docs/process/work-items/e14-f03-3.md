Sub-issue of #58. `infra/observability/` contains exactly one file — `otel-collector-config.yaml`, 68 lines — and that
file says in its own header comment: "Redaction processors and sampling rules arrive with #58." Its three pipelines all
end at the `debug` exporter, so nothing is stored and nothing can be queried: there is no Prometheus, no Loki, no Tempo,
no Grafana and no Alertmanager anywhere in the repository (`ls infra/observability` and `grep -rn
"prometheus\|grafana\|loki\|tempo\|alertmanager" infra/` confirm it). Plan decision **D13** requires exactly this: the
self-hosted Prometheus/Loki/Tempo/Grafana/Alertmanager stack "stays in `infra/observability/` as a compose profile for
development, air-gapped on-prem installs and game days". Without it, the dashboards of the next sibling and the alert
rules of the one after have nowhere to run and no way to be evidenced.

## What is missing

- Any redaction or sampling processor. The collector today forwards whatever the hosts send, which makes the redaction
  obligation of `docs/nfr/data-classification.md` section 8 a single-layer control living only in `LogRedaction`. The
  collector is the second layer, and it is the only one that also covers the client telemetry of
  #52 and anything a library emits that the application did not construct.
- Any storage or query backend, so no dashboard and no alert rule can be written, run or evidenced.
- Any tail-sampling policy, so the 10% head sample in `ObservabilityOptions.TraceSamplingRatio` is the only control and
  an erroring request is as likely to be dropped as a healthy one.

## Acceptance criteria

- [ ] `docker compose -f infra/compose/docker-compose.yml --profile observability up -d --wait` brings the collector and
      all five backend services to healthy, and `./scripts/dev status` reports each one.
- [ ] With a host running against the collector, a trace appears in Tempo, a metric series appears in Prometheus and a
      log record appears in Loki, all three queryable by the same `CorrelationId`.
- [ ] **Negative — the redaction backstop:** a span, a metric and a log record are pushed into the collector carrying
      sentinel values under each prohibited attribute name of `docs/nfr/data-classification.md` section 8 — including an
      `Authorization` header attribute, a `measurement` attribute and a `/c/**` path — and **none** of the sentinels is
      retrievable from any of the three backends afterwards. This is the test that proves the collector is a second
      layer and not a pipe.
- [ ] **Negative:** no port of any new service is reachable on a non-loopback address, and no secret appears in any
      compose or configuration file as an environment variable or a literal (`infra/CLAUDE.md` sections 2 and 3); the
      infrastructure scan job of `.github/workflows/ci.yml` passes.
- [ ] **Exception:** with `Observability:OtlpEndpoint` empty, both hosts start, export nothing and pass their probes
      with the profile **down** — the stack is optional, in development and in production alike, and a deployment that
      never brings it up is a supported deployment.
- [ ] Tail sampling keeps every errored trace: a forced 500 is retrievable in Tempo even with the head ratio at its
      default.

## Environment this can be verified in

**Every acceptance criterion in this issue needs a running Docker daemon**, and `./scripts/dev doctor` in the planning
container reports none. This issue therefore cannot be *evidenced* from a container without Docker, even though the YAML
can be written there. Run it on a Docker-capable machine. Two consequences for the session, to decide **before** writing
any YAML rather than after:

1. Run `./scripts/dev doctor` first (DOR-16) and stop if it reports no Docker daemon — say so in the issue and hand the
   recorded run to someone who has one, rather than writing six services' configuration that nobody can start.
2. The architecture-tier `ComposeConfigurationTests` **do** run without Docker: they parse the compose files. They are
   the part of this issue that is verifiable anywhere, and they are what catches a `TAILOR360_…`/`__`-separated key that
   binds to no options property. None of the five new services sets an application configuration key, so the expected
   result is "still green", not "a new assertion".
