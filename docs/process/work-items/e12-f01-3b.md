Sub-issue of #50. The home screen is a placeholder. `HomeRoute` in `clients/pwa/src/app/router.tsx:49-60` is two
message ids — `home.title` and `home.body` — under a comment reading "Placeholder home screen. The role dashboards
arrive with #50 and the feature milestones". It is the index route behind `RequireSession`, so it is the **first
screen every signed-in person sees**, and it offers them nothing: no way to start work, and no second route to
anything in the navigation.

This slice replaces it with a destination launcher built on the hook **e12-f01-3** introduces: the same destinations
that person's permissions and the registered routes already allow, as large cards, with one line saying what each is
for. It is deliberately separate from e12-f01-3 — that slice rebuilds the navigation for twelve permission sets, and
a new screen with its own states, stories, message ids and axe assertions appended to it is a second session, not a
larger first one (the calibration in this repository: one non-trivial route is most of a session).

It also satisfies **2.4.5 Multiple Ways** for the whole application in one place, by being a second route to
everything the navigation offers.

## What is already built (do not re-build)

- `clients/pwa/src/app/router.tsx:172` — `{ index: true, element: <HomeRoute /> }` inside the `RequireSession`
  children. The route already exists; only the element changes. `HomeRoute` itself is declared in the same file
  (lines 49-60) alongside `DisplaySettingsRoute` and `NotFoundRoute`.
- **`useSessionNavigation()` from e12-f01-3** — the permitted destinations in `SECTION_ORDER` order and the primary
  action, each already filtered by "permission held **and** route registered". This slice calls it and filters
  nothing itself. If it finds itself re-deriving permissions, the hook is being bypassed and the review will say so.
- `clients/pwa/src/components/primitives/` — `Card` (with `Card.css`), `Button`, `ButtonGroup`, `Icon`, `TextLink`,
  `Alert`, `StatusBadge`, each with a test, a story and an axe assertion, plus `icons.ts` for the glyph names the
  destination table already uses.
- `clients/pwa/src/components/states/EmptyState.tsx` — the empty state, and the same component
  `clients/pwa/src/admin/RequirePermission.tsx` renders for a refusal. Reuse it; do not write a second one.
- `clients/pwa/src/components/layout/` — `RouteAnnouncer` already moves focus to the page heading on navigation, so
  this screen needs an `h1` and nothing else to satisfy that. `ShellStatusProvider` is provided by `AppShell`;
  `useShellStatus()` **throws** outside it, and this screen has nothing to announce, so it must not call it.
- `clients/pwa/src/i18n/messages/shell.ts` and `messages/navigation.ts` — the two catalogues that own shell and
  destination wording, both languages in each file. `MessageCatalogue` in `en-IN.ts` fails the type check when a key
  exists in one language and not the other.
- `clients/pwa/src/auth/testing/fixtures.ts` (`stubFetch`, `jsonResponse`, `aCurrentUser`) and the harness pattern in
  `clients/pwa/src/auth/RequireSession.test.tsx`: `AppIntlProvider` + `MemoryRouter` + `SessionProvider` over a
  stubbed `fetch`. `design-system/testing/renderWithProviders.tsx` supplies no session and no router and cannot
  render this screen. `clients/pwa/src/admin/testing/storyTransport.tsx` is the **admin** harness and is not this
  one.
- `clients/pwa/.storybook/preview.tsx` — the four toolbar globals (locale including the pseudo-locale, theme
  including high contrast, text size, density) and the five viewport widths (320, 360, 768, 1024, 1280). Stories get
  these for free.

## Acceptance criteria

- [ ] A Cashier signs in and lands on a screen whose cards are exactly the destinations
      `useSessionNavigation()` offers them, minus Home and Settings, in `SECTION_ORDER` order — asserted through
      the rendered links, not by calling the hook.
- [ ] Each card's accessible name is identical to the same destination's name in the shell navigation: asserted by
      reading both from the rendered output in one test, because "identical" is the property that makes the second
      route usable.
- [ ] Every card's href resolves to a route registered in `clients/pwa/src/app/router.tsx` — derived from the
      router's own route objects, not a re-listed array.
- [ ] The primary action, when the hook offers one, is the first focusable element after the heading and points at
      the same href as the phone shell's floating action.
- [ ] Negative: a session with an empty permission list — the fail-closed state
      `clients/pwa/src/auth/types.ts:119` documents — sees an `EmptyState` naming who to ask, not a blank page and
      not a grid of zero cards with a heading that implies something is loading.
- [ ] Negative: the hook offers no primary action — no button is rendered, and no disabled button is rendered.
- [ ] Exception: `useSession().status` is `loading` — the heading and lede render and no cards do, with no skeleton
      and no spinner; nothing on this screen is fetched, so a skeleton would be a lie about a request that does not
      exist.
- [ ] Exception: the device is offline — the screen renders completely, because it fetches nothing. Assert it, so
      nobody later adds a request to it without noticing that this criterion breaks.
- [ ] Axe is green on the screen for all three permission sets and for the empty case, through
      `clients/pwa/src/design-system/testing/axe.ts`, and the pseudo-locale story renders without clipping at
      320 px.
