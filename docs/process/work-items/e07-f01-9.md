Sub-issue of #35, and the last of them. It is the parent's acceptance criterion 4 — "**Labels scan at approved
size/contrast on representative devices/printers**" — and the W3 exit gate "labels printed and scanned on real
devices" (plan Section 6.2). E07-F01-8 built the instrument: the label content policy, the `label-sheet` command, the
committed sheets, the record template and the empty index. **This issue takes the readings.**

> **This is not a coding session.** It is a hardware rehearsal recorded by a person at the head branch, and a coding
> agent cannot complete it: it needs a nominated thermal label printer with its stock, an A4 printer, a USB or
> Bluetooth keyboard-wedge scanner, an Android phone, an iPhone or iPad, and a print-station device. An agent may
> prepare the pull request's shape — the record files from `TEMPLATE.md`, one per combination, with the index rows
> moved from `pending` to the combination's name — and must then stop. **A scan result that was not observed is never
> written.** A fabricated row here would be the one kind of evidence this project cannot recover from: every later
> release gate reads these records as proof that the shop's labels work.

## Acceptance criteria

- [ ] For **each** nominated printer and template combination there is a record carrying the regenerated sheet, the
      command line that produced it, a photograph of the printed output, and a scan result for **all three** sources,
      with device, operating system and browser versions named — the minimum
      `docs/process/definition-of-done.md` section 4 line 163 sets for a label.
- [ ] One record is of a label queued from a phone and printed by a station, with the print job identifier and the
      Verify outcome shown.
- [ ] **Negative:** every label on the invalid-payload sheet is **refused**, with the expected code recorded per
      source, and nothing on that sheet resolves to a garment job.
- [ ] **Negative:** no record, photograph or sheet contains a real customer name, telephone number or measurement,
      and no photograph has a garment, a customer or other paperwork in frame — the photograph is of a label
      (CLAUDE.md section 4 item 10).
- [ ] **Exception:** where a combination cannot be run — the printer, the stock or a scanner is not available at the
      head branch — the index row reads `deferred — <reason>` and carries the **six-field** deferral record of
      `docs/process/definition-of-ready.md` section 5, escalating to a dated, owned waiver in
      `docs/process/waivers.md` only if it reaches a release. The issue does **not** close with an empty table, and
      it does not close by deleting the row.
- [ ] The durability note records at least one dated observation per factor and says where a factor could not be
      observed yet.
- [ ] The three traceability status cells say what the records prove and no more; **NFR-CB-04** stays open if OD-09
      is still open, with the recommendation attached rather than the decision assumed.
