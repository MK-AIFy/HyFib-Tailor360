Sub-issue of #40. #40 bundles four features — low-stock alerting, stocktake, operational stock reports and
valuation — and its own blueprint (`docs/IMPLEMENTATION_PLAN.md` Section 9, `### #40`) lists them as four separate
paragraphs, so it cannot be one pull request. This is the first of eleven children and the smallest honest starting
point: the **branch alert policy** that every later alert decision reads, and the **pure evaluator** that turns a
balance, a reorder rule, an open purchase quantity and that policy into a low-stock verdict. Checked in this working
copy today: `src/Modules/Inventory/` is 12 files and 122 lines of C# scaffolding (`AddInventoryModule` returns
`services` unchanged; `InventoryEndpoints.MapInventoryEndpoints` maps an empty group at `/api/v1/inventory`), and
`grep -c "api/v1/inventory" docs/api/openapi.v1.json` returns `0`. There is no `alert_policies` table, no evaluator
and no alert anywhere in `src/`.

## Acceptance criteria

- [ ] A Branch Manager holding `inventory.manage_reorder_rules` reads the policy for their branch over HTTP, changes
      it with the `If-Match` from that read, and sees the new values on the next read — with no direct database
      access in the test.
- [ ] Both routes declare exactly one permission, exactly one rate-limit policy and (for the `PUT`) an audit action
      and idempotency (ARCH-007, ARCH-008, ARCH-017); `AuthorisationMatrixTests` passes with the new section 5 rows.
- [ ] **Negative:** a caller at branch B reading or writing branch A's policy is answered as if it did not exist —
      the branch is never taken from the request. A caller without the permission is refused `403`
      `security.forbidden`, matching the `not-permitted` answer in `matrix.yaml`.
- [ ] **Negative:** a `PUT` with no `If-Match` is refused `428` and one with a stale `If-Match` is refused `409`
      carrying `currentVersion`, per `docs/architecture/conventions.md` section 4.2; a replayed `Idempotency-Key`
      returns the first outcome rather than applying the change twice.
- [ ] **Exception:** a policy naming a role key that `SystemRoles` does not declare, a negative hysteresis margin or
      a negative escalation delay is refused with an RFC 9457 problem detail naming the field — never a database
      error and never a silent coercion to zero.
- [ ] The evaluator's verdict is a pure function of its arguments: the same inputs give the same verdict, it reads no
      clock and no ambient state (it takes `DateTimeOffset` as a parameter where it needs one, ARCH-014), and a
      balance moving back above the reorder point **plus** the hysteresis margin is the only input that produces
      `Cleared`.
