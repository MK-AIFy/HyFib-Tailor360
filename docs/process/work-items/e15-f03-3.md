- [ ] Negative case: a scenario asserting a refusal — in walkthrough 1, a reprint without a reason is refused, and
      the refusal is an RFC 9457 problem-details body with a field error, not a stack trace (`CLAUDE.md` section 4
      rule 3).
- [ ] Negative case: the suite fails when the application is wrong rather than when it is slow — a deliberately
      broken build is run once and the failure output (screenshot, trace, video) is attached, proving the artefacts
      are actually captured.
- [ ] Exception case: walkthrough 2's quality-control failure and rework path is asserted to **keep history** — the
      failed result, its defect code and the rework task all remain readable after the garment passes on the second
      attempt.
- [ ] The CI job runs on the branch and uploads its artefacts; a red scenario fails the job.
- [ ] Run twice: the two scenarios pass in two consecutive runs with no shared state carried between them
      (`CLAUDE.md` section 5).
