Sub-issue of #51. The progressive web application is installable today but has **no service worker**: nothing
registers one, nothing is precached, and an offline reload shows the browser's error page.
`clients/pwa/vite.config.ts` already carries the decision in its comments — `registerType: 'prompt'`,
`manifest: false`, `injectRegister: null`, with the note "#20 ships no service-worker registration: the update
prompt, the offline queue and the encrypted drafts belong to #51". This sub-issue is the first half of that:
registration, the precache, and a caching policy that can only store what is on an explicit allowlist. The update prompt
is #E12-F02-2; the device store is #E12-F02-3a, the measurement drafts #E12-F02-3b, the queue #E12-F02-4, and its
surfaces #E12-F02-5a and #E12-F02-5b.

- `clients/pwa/src/auth/apiClient.ts` — `send()` already sets `cache: 'no-store'` on every request. That governs the

- `clients/pwa/src/app/version.ts` (`VERSION_ENDPOINT`, `fetchVersion`, `useVersion`) and
  `clients/pwa/src/app/clientVersion.ts` (`CLIENT_VERSION`, `X-Client-Version`) — the compatibility handshake. This

- [ ] `GET /api/v1/catalog/current` is answered from the reference cache while offline and revalidated when the
      connection returns; `GET /api/version` is never served from a cache.
- [ ] A catalogue answered from the reference cache carries the **visible staleness marker** on
      `MeasurementStartRoute`, stating when it was last read, as icon and words and not as colour alone; it is
      announced politely and it disappears on a successful revalidation (`docs/nfr/support-matrix.md` section 7.4,
      **A11Y-OF-05**).
- [ ] The offline banner is persistent and announced and stays until the connection returns — **A11Y-OF-01**,
      satisfied by the existing `NetworkStatusBanner`, which this issue makes reachable offline for the first time
      and therefore must verify rather than assume.
- [ ] After a new build is deployed, activation deletes every cache whose name does not carry the new
      `CLIENT_VERSION`, and the shell copy is refetched rather than reused.
- [ ] **Negative:** a response carrying `Set-Cookie`, `Cache-Control: no-store`, or a status other than 200 is not
      stored even when its path is on the allowlist — `isStorable` returns false and a named test proves it.
- [ ] **Negative:** a catalogue read that reached the network shows **no** staleness marker. A marker on fresh data
      is the failure that teaches people to ignore it.
- [ ] **Negative:** signing out deletes the reference and shell caches, so the next person on a shared counter
      device cannot read the previous person's branch catalogue from the device.
- [ ] **Exception:** registration failing — no service worker support, an insecure context, a refused registration —
      leaves the application fully functional online, logs nothing personal, and shows no error to the user.
- [ ] Every script the shell loads still executes: the nonced module script and its `modulepreload` links are
      unaffected, and a navigation served from the shell cache carries the content-security-policy header it was
      stored with.
