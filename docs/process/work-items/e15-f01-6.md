- **How the stack already sequences the migration, which changes what the script must do.**
  `infra/compose/docker-compose.staging.yml` declares `migrate` as an ordinary service (line 205, `command:
  ["migrate"]`, `restart: "no"`, `healthcheck: disable: true`) and **both `web` and `worker` depend on it with
  `condition: service_completed_successfully`**. So `docker compose up -d --wait --pull always` **runs the migration
  itself**, before either host may serve. The script must therefore *not* run a separate `run --rm migrate` and then
  `up` — that migrates twice. Read the file and write the flow it actually supports.
  The preflight is the one thing that does need its own invocation, because the service's `command` is fixed: it is
  `docker compose -f … run --rm --no-deps migrate migrate --preflight` (the trailing arguments replace the service's
  command entirely, so the verb has to be repeated), and `--no-deps` keeps it from starting the rest of the stack.
  Paste the resolved command in the pull request.
