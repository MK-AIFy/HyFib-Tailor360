Sub-issue of #56. Plan Section 8 gives the W5 half of this parent an "automated security regression suite (IDOR,
escalation, **workflow bypass via direct API**, **barcode replay**, …)" and, separately, "**business-state
authorisation checks (no client-driven state)**". **This sub-issue takes those three: `ABF-03` workflow bypass
through a direct API call, `ABF-04` barcode replay, and the no-client-driven-state rule as an enforced test.** They
belong together and apart from `ABF-01` and `ABF-02`: the authorisation families ask *may this caller touch this
record*, which the authorisation matrix machinery already answers per request; these three ask *may the system be in
this state*, which needs a **sequence of business state** and a different body of domain reading — estimates,
phases, ready gates, labels and custody events.

The parent's third acceptance criterion — "workflow/payment/stock/barcode business rules cannot be bypassed through
direct API calls" — is answered for **workflow and barcodes** here, and for payments and stock by two further
siblings.

The gap is checkable today: `ls tests/Tailor360.IntegrationTests/Security` returns `ContentSecurityPolicyTests.cs`,
`CrossSiteDefenceTests.cs`, `ErrorLeakTests.cs`, `ForwardedHeaderTests.cs` and `ResourceScopePipelineTests.cs` —
five files, none of which tests a sequence. And nothing anywhere asserts the no-client-driven-state rule as a rule:
it is stated in plan Section 8 and enforced nowhere.

## What is missing

- No test performs a workflow **sequence**: confirm an order whose estimate was never accepted; advance a phase twice
  from the same prior state; record a result against a cancelled or held job; dispatch a job the gate has not cleared.
- No test performs a custody **sequence**: scan a label another branch already dispatched; re-present an invalidated
  label; scan the same label twice.
- Nothing asserts the no-client-driven-state rule at all. A new endpoint that trusts a client-supplied `status`,
  `total` or `branchId` would pass every check the repository has today.
