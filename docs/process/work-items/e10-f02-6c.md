## Scope

- [ ] **One synthetic history generator**, in the integration test project beside `ReportingScenes.cs`, that publishes
      a deterministic event stream at the cited volume: one year of garment lifecycles at
      `capacity-and-performance.md` section 2.2's rate (36,000 garment jobs, 115 on a mean day) across the two seeded
      branches, with phases, holds, reschedules, cancellations, QC outcomes, reworks, alterations, assignments and
      reassignments in realistic proportions. Deterministic from a fixed seed, so a failure is reproducible, and
      **synthetic only** — no production data is ever copied into a fixture (CLAUDE.md section 4 rule 10).
- [ ] **Rebuild equals live, across the whole #45 set, in one test**: build every #45 projection by live dispatch,
      snapshot all nine tables, run `rebuild-projection` for each, and assert equality table by table and column by
      column. This is the parent's fifth acceptance criterion proved end to end; the per-slice versions stay where
      they are.
- [ ] **Rebuild is deterministic under re-ordering**: the same stream dispatched in a different interleaving across
      aggregates produces the same projections, which is what makes the equality above a property rather than a
      coincidence of one ordering.
- [ ] **Performance at production-sized history**: with the generated history in place, measure each of the nine read
      routes against the **report and read-model query budget of `capacity-and-performance.md` section 3.3**, and
      measure projection lag against the **S9 row** while the stream is being dispatched. The numbers come from those
      rows, are cited in the assertion message, and are never restated as this issue's own.
- [ ] **The measurement is recorded, not claimed**: a table of route, volume, p95 and the document row each budget is
      quoted from, pasted into the pull request. A claim without numbers is not evidence (Definition of Done item 9).
- [ ] **A failure is a finding, not a silent skip**: if a route misses its budget, the pull request records the
      measured figure, names the query, and either fixes it within this slice (an index on the projection is in scope)
      or raises a new issue linked to #45 with the measurement attached. Adding an index to a `reporting.*` table is in
      scope and is one expand-only migration named `ReportingProjectionIndexes`; changing a projection's **shape** is
      not, and goes back to the slice that owns it.
- [ ] **Where it runs is recorded.** The volume tier needs a real database rather than a container on a shared runner;
      the pull request says which, with `./scripts/dev doctor` output beside it.

## Acceptance criteria

- [ ] The generator produces the cited volume deterministically from a fixed seed, and a second run from the same seed
      produces an identical stream.
- [ ] **Rebuild equals live for all nine #45 projection tables in one test**, row for row and column for column,
      including `held_seconds_total`, the daily workload counts, the quality counters and the merge folds.
- [ ] **Re-ordered delivery agrees:** the same stream interleaved differently across aggregates produces identical
      projections.
- [ ] Each of the nine read routes is measured at the cited volume, and each measurement names the
      `capacity-and-performance.md` row it is judged against.
- [ ] Projection lag stays within the **S9** row while the stream is dispatched, measured from
      `projection_checkpoints` rather than asserted.
- [ ] **Negative — a deliberately slow query:** a test or a recorded run shows the measurement actually fails when a
      budget is missed, so a green result is not a measurement that never ran. Removing an index and re-measuring is an
      acceptable way to show it.
- [ ] **Negative — branch scope survives volume:** at full volume, a caller assigned to one branch still receives no
      other branch's rows from any of the nine routes. Volume is exactly when a filter-inference defect hides.
- [ ] **Exception — the tier cannot run here:** if no real database is reachable, the tier **fails** rather than
      skipping quietly, and `CI=true` makes that a build failure (CLAUDE.md section 5).
