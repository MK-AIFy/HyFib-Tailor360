Sub-issue of #49. Nothing in the system can read a feedback response or a service-recovery case: `feedback.read` is
declared in `src/Platform/Tailor360.Platform.Security/Permissions/NotificationsPermissions.cs` and reserved to #49
in `docs/security/permission-matrix.md:217`, and no route demands it — `NotificationsEndpoints.cs` maps an empty
group. #213 lands the tables and the case lifecycle but states in its own acceptance criteria that "nothing in this
sub-issue exposes a customer-facing endpoint" and that the staff endpoints "under `feedback.manage_cases` /
`feedback.read` … are #49's work". This slice is the **row-level** read half of that surface: four routes and the
free-text visibility rule that governs them. It changes no state, so it is the slice that can be reviewed for
privacy on its own.

**The metrics route, the metric dictionary and the customer-timeline entry kinds were in this slice and have been
split out into [E11-F03-3b].** Four row-level reads with their payloads, queries, keyset paging, filters and a new
`Platform.Security` response-view file already run to about 1,100 production lines on this repository's own
calibration — `clients/pwa/src/routes/catalog/CatalogVersionEditorRoute.tsx` is 994 lines for one route and
`CatalogDesignRoute.tsx` is 1,269 — and adding a five-dimension aggregate with percentiles, a metric dictionary
under a `docs/reports/` directory that does not yet exist, and three entry kinds on a timeline source that #212 has
not merged took it past a session. The split also removes the conditional acceptance criterion this body used to
carry ("if #212 has not merged, the timeline kinds move to a follow-up"), which is not a criterion a reviewer can
verify.

## Scope

- [ ] `GET /api/v1/notifications/feedback/responses` — the branch's responses, newest first, keyset-paged, filtered
      by date range, overall-rating band, `alterationRequested` and whether a case is open. Card payload only:
      ratings, order and garment display numbers, the instant, `hasComment` as a boolean — **never the comment**.
      `RequirePermission(feedback.read, BranchScope.AssignedBranches)`,
      `TouchesNoBranchOwnedResource(…, "#49")`, `RateLimitPolicyNames.DefaultUser`, `RequestTimeoutPolicies.Read`.
- [ ] `GET /api/v1/notifications/feedback/responses/{responseId:guid}` — one response in full, including the
      comment. `ScopedToResource("notifications.feedback_response", "responseId", BranchScope.AssignedBranches)`
      (ARCH-023) and `.Audited("notifications.feedback.comment_read")` — a read that is audited **because the read
      itself is sensitive**, which `CLAUDE.md` security rule 5 provides for and `data-classification.md` 5.4 already
      does for the measurement sheet.
- [ ] `GET /api/v1/notifications/feedback/cases` — the service-recovery queue: status, owner, due instant, overdue
      flag, escalation rung, the order and garment it is about, and why it was opened (low rating or alteration
      request) as a code. Same permission, scope, policy and timeout as the responses list.
- [ ] `GET /api/v1/notifications/feedback/cases/{caseId:guid}` — one case with its contact attempts, its resolution
      code if closed, its alteration reference if any, and the response it came from — the comment included, under
      the same view rule and the same explicit audit as the response detail.
      `ScopedToResource("notifications.service_recovery_case", "caseId", …)`.
- [ ] `src/Platform/Tailor360.Platform.Security/FieldVisibility/NotificationsResponseViews.cs` — two views,
      `notifications.feedback_card` (no comment field at all) and `notifications.feedback_response` (the comment
      declared `FieldClassification.CustomerNotes` with its rationale traced to `data-classification.md` 5.14),
      both `ViewSurface.Counter` (the enum has exactly two members, `Workshop = 0` and `Counter = 1` — verified),
      registered in `ResponseViewCatalogue`, and a section added to `docs/security/field-visibility.md` in the same
      pull request. `ViewField` is `(string Name, FieldClassification Classification, string? RequiredPermission,
      string Rationale)` — verified, so the rationale string is mandatory and is where the 5.14 citation goes.

## Acceptance criteria

- [ ] A Branch Manager of branch A opens the queue and the response list for branch A over HTTP and sees only
      branch A's rows; a member of staff assigned only to branch B gets none of them, and the answer is the same
      shape as an empty branch rather than an error that confirms rows exist.
- [ ] Rule-level: all four routes declare `feedback.read` with a branch scope (ARCH-007), exactly one rate-limit
      policy (ARCH-017), and the two routes with an identifier declare `ScopedToResource` (ARCH-023); the two
      sensitive reads declare `.Audited(…)` although they change nothing. Auditing a read is precedented, not novel:
      `Tailor360.Modules.Billing.Api/Payments/ReceiptEndpoints.cs:51` audits a receipt download and
      `Invoicing/InvoiceEndpoints.cs:369` and `:390` audit document downloads — verified. A row for each route is
      added to the `<!-- matrix:endpoints -->` block (lines 311–512), because `AuthorisationMatrix.Reconcile` fails
      and names a published route that is missing.
- [ ] The comment appears in exactly two payloads — the response detail and the case detail — and in neither list
      and no log line. A test enumerates the serialised bodies of all four routes and asserts the comment string is
      absent from the two lists.
- [ ] Reading a comment writes one audit event naming the response and the actor, and no audit event carries the
      comment itself.
- [ ] Negative: a caller holding no `feedback.read` gets `403` with `security.forbidden`; an unauthenticated caller
      gets `401` with `security.authentication-required` — the answers named in
      `tests/Tailor360.IntegrationTests/Authorization/matrix.yaml`.
- [ ] Negative: a response identifier belonging to another organisation, and one belonging to a branch the caller is
      not assigned to, both answer `404` — not `403`, which would confirm the row exists. The chosen answer is
      recorded in `matrix.yaml`'s `identifier-editing` section, as its header instructs.
- [ ] Exception: a list over a window, a rating band or a filter combination that matches nothing answers `200`
      with an empty page and a null continuation cursor — not `404`, and not an empty body.
- [ ] Exception: a keyset cursor that has been tampered with, or one from a different filter set, is refused with a
      stable problem code rather than silently re-reading from the start, which would loop a client for ever.
