## Acceptance criteria

- [ ] **Step 7:** the doorstep screen records a handover with a typed recipient name and the six-digit code, shows the
      attempts left, and completes without any dragging interaction at all.
- [ ] **Step 8:** a failed delivery is recorded with a configured reason code and the screen says the garment returns to
      the branch and that a new authorisation will be needed.
- [ ] **Negative:** a wrong code increments the visible attempts-used count; the exhausted case says the delivery must
      be re-attempted under a new authorisation rather than repeating "wrong code"; an expired code reads identically to
      a wrong one, because the server answers identically.
- [ ] **Negative:** the signature pad is never the only way to complete a handover — with the branch policy set to
      signature the typed-name-plus-code path is still offered (A11Y-78), and a test asserts it.
- [ ] **Negative:** the forbidden state of each screen renders `RequirePermission`'s `EmptyState` with
      `admin.forbidden.title` / `admin.forbidden.body` and none of the screen's controls, driven by `permissions: []`.
- [ ] **Negative:** a `409` from a replayed confirmation renders the conflict in plain language with the current state
      and what to do, never as a generic failure and never as a success.
- [ ] **Exception — step 9:** offline, a submitted confirmation shows as "delivered — not yet synced" and **never** as
      delivered, and the **Send code** action shows `OfflineBlockedAction` with plan Section 4.6's exact sentence —
      "Needs connection — this will not be queued", which `OfflineBlockedAction.test.tsx:15` asserts word for word —
      beside the form, with the typed recipient name intact. Navigating from an offline story to any other story leaves
      that story online, because `useNetworkState` keeps one module-level snapshot per document.
- [ ] Every write carries one `Idempotency-Key` across its retries, so a double tap or a lost response records one
      outcome; asserted in the route tests by inspecting the stub's received headers.
- [ ] `pnpm --dir clients/pwa lint`, `typecheck`, `format:check`, `test`, `build`, `build-storybook` and
