Sub-issue of #49. There is no Notifications or feedback screen in the client at all: `clients/pwa/src/` has feature
folders for `admin`, `billing`, `measurements`, `catalog` and `customers` and none for feedback, and
`clients/pwa/src/app/router.tsx` has no route under `/service-recovery`. The staff who are accountable for EX-11 —
Branch Manager and Reception (`docs/prd/raci.md` row 21) — therefore have nowhere to work a case even once the two
backend siblings have merged. This slice is the **first half** of the operational surface: the feature folder every
feedback screen needs, and the queue route. **The case detail route and its three commands are [E11-F03-6b].**

**Why it was split.** The proposal put both routes in one session at 1,000 estimated production lines. This
repository's own merged code says otherwise: `clients/pwa/src/routes/catalog/CatalogVersionEditorRoute.tsx` is 994
lines for one route and `CatalogDesignRoute.tsx` is 1,269, both before their entry components, their API module,
their messages and their stories, and commit `5f99c6a` — "design administration screens for groups, options and
rules" — added 3,192 production lines across 21 files. A queue with two tabs, filters and a metrics strip, plus a
case detail with a timeline and three command dialogs, plus an API module, types, problems, a two-locale message
family and a stylesheet, lands between 1,750 and 2,100 production lines. That is two sessions, and CLAUDE.md section
6 targets under about 1,500. The reason the proposal gave for not splitting — "a detail screen with no queue to
reach it from" — does not survive contact with the repository either: a route with an identifier is reachable by URL,
`MasterDetail` already exists, and [E11-F03-6b] depends on this slice for the queue that links to it.

One route, two tabs, and the shared foundation; no new backend work.

## What is already built (do not re-build)

- `clients/pwa/src/auth/apiClient.ts` — `apiRequest<T>(path, options)` and `apiRequestVersioned<T>()`, `ApiError` /
  `ApiProblem` (RFC 9457), and the `IDEMPOTENCY_HEADER`, `IF_MATCH_HEADER` and `ETAG_HEADER` constants. Never call
  `fetch` from a screen, and **do not edit this file** — it is one of the single-session shared files. A new problem
  code belongs in the feature's own `feedbackProblems.ts`.
- `clients/pwa/src/admin/useAdminResource.ts` — `useAdminResource<T>(key: string, read: (signal) => Promise<T>)`
  returning `{ value, failure, loading, reload }`. The dependency is a **string key**, not an array; the read is
  held in a ref; a reload keeps the old value on screen. Every read-then-command screen reuses it rather than
  hand-rolling an effect, and there is no shared server-state cache yet (its own doc comment says TanStack Query is
  still to arrive).

  `useCurrentUser()` and renders an `EmptyState` with the message ids `admin.forbidden.title` /

  the server re-authorises every call.
