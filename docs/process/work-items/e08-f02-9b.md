## Acceptance criteria

- [ ] An Inventory Clerk holding `inventory.record_movement` transfers a quantity between two locations of the branch
      from `/inventory/transfers/new`, sees the conversion sentence when the entered unit is not the base unit, reads
      both locations back in the confirmation, and lands on a result naming the transfer and both ledger entries.
- [ ] The destination picker offers **only** the source's allowed destinations, and changing the source re-reads them
      rather than leaving a stale list.
- [ ] **Idempotency:** the key is minted once when the person commits, is unchanged across a retry of a failed submit,
      and is replaced only after a success — asserted by failing the first request and inspecting the header on the
      second.
- [ ] **Offline:** the submit is refused through `OfflineBlockedAction` with words, posts nothing and queues nothing.
- [ ] **Negative:** a caller without `inventory.record_movement` sees the `RequirePermission` empty state
      (`admin.forbidden.title` / `admin.forbidden.body`) and is **not** redirected; an insufficient-stock refusal
      renders as a sentence; a source location with no allowed destination renders an `EmptyState` naming the location
      admin screen rather than an empty dropdown.
- [ ] **Exception:** a destination that was allowed when the form loaded and is refused at post time — retired, or
      removed from the set — renders `inventory.transfer-destination-not-allowed` as a sentence and keeps the input.
      The server is the authority and the client's list is never treated as one.
- [ ] **Accessibility:** every field has a persistent visible label; `expectNoAccessibilityViolations` passes in each
      state; `expectNoHorizontalOverflow` passes at all its default widths; the error summary moves focus to the first
      invalid field.
- [ ] **Localisation:** every string is in both `inventoryEn` and `inventoryTa`; quantities render through
      `formatters.formatQuantity` and typed decimals parse through `parseDecimal`.
- [ ] `pnpm --dir clients/pwa lint`, `typecheck`, `test`, `format:check` and `build` pass, and `generate:api:check` is
      clean — the schema was regenerated by `E08-F02-6`, not here.

## Data and classification

`docs/nfr/data-classification.md` section 5.9 — **Confidential**.

| Item | Class | Purpose | Retention | Who may read it | Logs, telemetry, export |
| --- | --- | --- | --- | --- | --- |
| Transfer form input (item, two locations, quantity, unit, reason) | Confidential | Post the balanced pair | **Nothing is persisted client-side** — no draft, no filter memory | The person entering it | Never in client telemetry; the request body is never logged (security rule 7) |
| The allowed-destination list | Confidential | Offer only destinations this source may send to | Not persisted client-side | Holders of the location read | Identifiers and names only |
| The idempotency key | Internal | Make one retry safe | Component state only | The client and the server | Safe to log as an identifier |
| The reason the clerk types | Confidential | Explain the movement | Stored server-side on both ledger entries | As the entries | **Free text a person wrote**: never in telemetry, and synthetic in every screenshot |
