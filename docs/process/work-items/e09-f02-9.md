Sub-issue of #42. The parent's **Required verification** asks for "PDF snapshot/accessibility … tests" and the
blueprint names them by intent: `PdfTotalsMatchSnapshot` over the #41 golden fixtures, "PDF snapshot with a Tamil
customer name and address", and "PDF accessibility check". None of the three merged children produced any of them.
`tests/Tailor360.IntegrationTests/Billing/DocumentArtifactTests.cs` asserts the **checksum** and the audit trail —
that the bytes have not changed — and never reads a figure out of the PDF. And no test project can read a PDF's text
at all: `grep -nE 'PdfPig|PDFsharp|iText|docnet' Directory.Packages.props` returns nothing.

This slice builds the capability and proves everything provable **without a database**, in the contract tier, against
the renderer. Its sibling **E09-F02-10** then proves the one thing that needs a live posting — agreement with the
*persisted* calculation snapshot — and prepares the accountant's review pack. They are two slices because the
renderer-level proof needs no scene and the snapshot-level proof needs a whole one; put together they are not one
session's work.

## What is already built (do not re-build)

- `src/Modules/Integration/Tailor360.Modules.Integration.Infrastructure/Documents/QuestPdfRenderer.cs` — the adapter.
  It is **already deterministic for a model** (creation and modification dates come from the model's `renderedAt`, so
  two renderings are byte-for-byte equal), already registers a Tamil-capable font pair
  (`DocumentFonts.Family = "Noto Sans"`, `TamilFamily = "Noto Sans Tamil"`), and already sets `DocumentMetadata` with
  `Title`, `Subject`, `Author`, `Creator`, `Producer` and **`Language = "en-IN"`**. The four template keys are
  `billing.invoice`, `billing.credit-note`, `billing.debit-note`, `billing.receipt`, exposed as
  `QuestPdfRenderer.InvoiceTemplate`, `.CreditNoteTemplate` and so on.
- `src/Modules/Integration/Tailor360.Modules.Integration.Infrastructure/Documents/BillingDocumentTemplate.cs` — what
  each document contains and the authority on field order. **Read its totals block before writing any assertion:**
  `Line(label, key, emphasis)` returns without printing when `amount == 0m && !emphasis`, so `Taxable value`,
  `Grand total` and `Balance due` are always printed and **`Discount`, `CGST`, `SGST`, `IGST`, `Cess` and
  `Round-off` are absent from the page whenever they are zero**. An assertion that expects `₹0.00` for IGST on an
  intra-state invoice will fail, and the fix is the assertion, not the template.
- `src/Modules/Billing/Tailor360.Modules.Billing.Application/Invoicing/DocumentModels.cs` — the map from an `Invoice`
  to the template's model: `Common(...)` builds `supplier`, `customer`, `placeOfSupplyStateCode` and `scheme`,
  `Totals(...)` the nine figures, `Taxes(...)` each component as `{kind, ratePercent, amount}`, and the invoice
  shape adds `totals["balanceDue"] = grandTotal`.
- `tests/Tailor360.ContractTests/Adapters/DocumentAdapterTests.cs` (267 lines) — **extend this file.** It already
  proves determinism (`RendersTheSameBytesTwiceForOneModelAndDifferentBytesForAnother`), the receipt roll, the
  Code 128 payload, the in-memory object store and the MinIO round trip. It constructs `QuestPdfRenderer` directly
  and has two helpers: `RenderAsync(renderer, template, model)` and `SampleModel(number)`.
- **`SampleModel` already carries a Tamil customer display name** — `"Synthetic customer மீனா"` — so the Tamil path
  is already *rendered* on every run of this file. What has never existed is an **assertion** that those code points
  survive into the PDF's text layer rather than becoming replacement glyphs or blank space. That is the gap, and it
  is smaller than it looks: the fixture is in place.
- `tests/Tailor360.ContractTests/Adapters/DocumentMoneyFormatTests.cs` — the money-formatting assertions over the
  document model. Do not duplicate them.
- `tests/fixtures/billing/pricing-golden-master.json` — **17 cases**, the accountant-shaped golden master from #147
  (OD-05). Top-level keys `registrationStateCode`, `overrideThresholdPercent`, `taxCodes`, `items`,
  `discountRules`, `cases`. Each case is
  `{name, taxInclusive, roundOff, placeOfSupplyStateCode, callerMayOverride, lines[], expected}`, where
  `expected.lines[]` carries `{lineKey, gross, discount, taxableValue, taxes{CGST…}, lineTotal, variance,
  approvalExercised}` and `expected.totals` carries the nine figures by the same names `DocumentModels.Totals` uses.
  The case names are prose with a prefix — `walkthrough-blouse: 450 + 90 + 40, intra-state, exclusive`,
  `inter-state: …`, `inclusive-exact: …` — so **key a case by its name's prefix before the colon**, and fail loudly
  when a prefix this slice names is no longer in the file. Every rate, code and amount in it is synthetic. **This is
  the fixture the document must agree with; do not write a second one.**
  Today it is read only by `tests/Tailor360.UnitTests/Billing/PricingEngineTests.cs`, a unit test over the engine —
  nothing has ever driven the renderer from it.
- `Directory.Packages.props` — central package management. The QuestPDF and ZXing.Net entries (lines 50–57) carry a
  comment block saying what each is for and what licence check it passed; **copy that shape.**
- `docs/nfr/a11y-checklist.md` section 5.6 (`A11Y-DP-01` to `A11Y-DP-09`), and section 1's scope note that the
  **printed artefact itself** is covered by the rendered-document requirements of
  `docs/nfr/accessibility-localisation.md` rather than by the on-screen checklist.
- `ARCH-009` (`docs/architecture/architecture-rules.md`): provider SDK packages are referenced only by
  `Integration.Infrastructure` **and by test projects**. A test-only PDF reader therefore needs no exception and no
  architecture decision record.

## What is missing

- No PDF text-extraction capability in any project.
- No assertion that a **figure printed on the page** equals the figure it was supposed to print.
- No assertion that the Tamil code points reach the text layer.
- No accessibility assertion over a rendered document at all.

- [ ] **`RenderedDocumentIsAccessibleAsFarAsTheRendererAllows`** in `DocumentAdapterTests.cs`, asserting what is
      machine-decidable:
      - the page's content is **real text**, extractable in reading order, and no page is a single image —

      - the metadata carries a `Title` and a `Language` (already set by the adapter, now pinned);

        **A11Y-DP-05**;
      - every printed amount appears on the same text line as its own label, so no figure is identifiable only by
        position — the assertable half of **A11Y-BI-03** and **A11Y-BI-05**.
- [ ] **Record the gaps the renderer cannot close**, in a short block comment at the head of the new test and

## Acceptance criteria

- [ ] For all 17 golden-master cases, every figure printed on the rendered invoice equals the fixture's expected
      figure to the paisa — read out of the PDF's text layer, not out of the model the renderer was handed — and a
      component the fixture expects to be zero is **absent** from the page.
- [ ] An invoice rendered with a Tamil customer name, address line and locality contains those Tamil code points in
      its extracted text, and the same document still renders its English labels in English.
- [ ] The rendered invoice's text is extractable in reading order, its metadata carries a title and a language, the
      line table's headings appear once above the rows, and every printed amount shares a text line with its label.
- [ ] **Negative:** a deliberately wrong figure fails. Prove it: alter one expected total in a scratch copy of the
      model, show `PdfFiguresMatchTheGoldenMaster` failing with **both** figures and the case name in the message,
      and revert. A golden-master test that cannot fail is not a test, and the transcript of that failure is
      evidence.
- [ ] **Negative:** with the Tamil font registration removed, `RendersTamilTextAsTamil` fails — demonstrated the
      same way, so the assertion is known to be reached rather than trivially true.
- [ ] **Exception:** a case whose `expected` the renderer cannot print at all (for example a component the template
      has no row for) fails with a message naming the case and the figure, rather than being skipped. No case is
      silently excluded; if one must be, the test names it in a list with a one-line reason each.
- [ ] **Exception:** the new package is referenced by `tests/Tailor360.ContractTests` only. `ARCH-009` stays green
      and `grep -rn "PdfPig" src/` returns nothing.
- [ ] Every fixture, name, address and amount used is synthetic (`CLAUDE.md` section 5).
