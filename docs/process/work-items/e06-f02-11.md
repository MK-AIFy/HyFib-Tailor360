## Scope

- [ ] `clients/pwa/src/routes/production/WorkboardRoute.tsx` at `/workboard` — the master-detail workboard: a filtered
      list of the branch's open phases on the left, the selected job's detail on the right through `MasterDetail`.
      Detail shows the job number, the category, the due cue **in text**, the pinned workflow version with its number,
      the phase list with each phase's status and timings, the current assignee, and the job's phase timeline through
      `Timeline`.
- [ ] **Assignment is never a drag**: `A11Y-RJ-04` step 3 is "Assign a job without a drag, using the row's own
      control", so every row carries its own assign control and any pointer affordance is an addition to it, never the
      only route. Drag-and-drop as a primary interaction is deliberately not built, here or in E06-F02-11b.
- [ ] Three commands, through `productionApi.ts`: start production
      (`POST /api/v1/orders/garment-jobs/{jobId}/production`), assign or reassign
      (`PUT /api/v1/orders/garment-jobs/{jobId}/phases/{phaseId}/assignment`) and unassign
      (`POST .../assignment/removal` — a `POST` and not a `DELETE`, because E06-F02-7 carries the mandatory reason in a
      body), each with `AdminReasonField` where the server demands a reason, each with an `Idempotency-Key` minted once
      by `crypto.randomUUID()` when the person commits and reused on retry, and each with `If-Match` from the read's
      `ETag`.
- [ ] Start production announces what it did and what it foreclosed: `A11Y-RJ-04` step 5 is "Start production, and
      hear that the workflow version is pinned and revision refused", so the confirmation states the pinned version
      number and that the order can no longer be revised. Use `ConfirmDialog`'s middle tier, because it is
      irreversible (INV-JOB-02).
- [ ] Refusals render as sentences naming the failing rule, not as codes: the five eligibility reasons E06-F02-7
      returns (`assignment.assignee-not-in-branch`, `assignment.assignee-not-active`,
      `assignment.role-not-permitted-for-phase`, `assignment.no-capability-for-category-and-phase`,
      `assignment.job-on-hold`) each get their own message id in the `production.*` family, phrased the way
      `clients/pwa/src/stories/fixtures/production.ts` phrases them.
- [ ] Filters shared with E06-F02-10's queue and stated in the URL so a filtered board can be shared with a
      colleague: assignment (mine, assigned, unassigned), state (overdue, blocked, held), priority, phase, and due
      within N days where **the person supplies N**. `A11Y-RJ-04` step 2 requires the filter set and the result count
      to be announced.
- [ ] List virtualisation on the list pane, per `docs/nfr/capacity-and-performance.md` line 334, sized for the
      peak-day volume the same document gives (346 garment jobs).
- [ ] The route mounted in `clients/pwa/src/app/router.tsx` inside `RequireSession`, wrapped in
      `RequirePermission permission={orders.read}`, with the assign and start-production controls hidden without
      `orders.assign` and `orders.start_production` respectively — the shape the catalogue and template routes already
      use, where the route is gated on the reading key and each action on its own.
- [ ] `clients/pwa/src/routes/production/WorkboardScreens.test.tsx` and stories in the existing
      `clients/pwa/src/routes/production/` story file, covering every state in the table below.
