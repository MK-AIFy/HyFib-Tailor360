Sub-issue of #41. The first half of the tax configuration editor: an accountant's rates **entered and saved**.
#145 built and tested all nine endpoints, and #41's blueprint asks for the editor —
"**Admin**: price/tax version editor with preview and test cases before publish"
(`docs/IMPLEMENTATION_PLAN.md` line 1850) — but no client screen reaches them: before E09-F01-4 there is no
`/admin/tax-configuration` route at all, and E09-F01-4 deliberately ships the register read-only, with no row link
and no "start a draft" control, because a link to an editor that does not exist is a dead end. This issue is the
editor up to and including the last save. **Validating and publishing a version is E09-F01-5b**, which is the next
slice and the first consumer of the shared findings list; the two are split because one session cannot carry both
under the 1,500-line target of CLAUDE.md section 6 — the closest analogue in this repository,
`clients/pwa/src/routes/catalog/CatalogVersionEditorRoute.tsx`, is 978 lines on its own before its forms.

## Scope

## Acceptance criteria

- [ ] An Owner starts a draft from the register, opens it, changes its name, notes and first day, adds a tax code
      with a classification and a CGST + SGST pair, edits that code, removes a second one, and reads everything
      back after a reload — no deployment, no database access.
- [ ] Cloning an existing version produces a draft carrying its codes, which is the ordinary way to change what is
      in force; the version cloned from is unchanged on screen after the clone.
- [ ] **Negative, the refused rate:** a rate outside the permitted range answers `billing.rate-out-of-range` and a
      malformed one `billing.rate-not-well-formed`, each as a field error attached to **its own component row**,
      never as one message for the whole form; a duplicate component answers `billing.component-duplicated`.
- [ ] **Negative, the code collision:** a second code with an existing spelling answers `billing.code-not-unique`
      against the code field, the typed values stay on screen, and a retry reuses the **same** `Idempotency-Key`.
- [ ] **Negative, concurrency:** a write made against a tag the screen no longer holds answers
      `billing.version-changed`, and the screen offers a re-read and a retry with the **same** `Idempotency-Key`,
      never a silent overwrite. The tag used for the next write is the one the previous response carried,
      **including after a `204` removal**.
- [ ] **Negative, authorisation:** a caller without `billing.manage_price_lists` meets `RequirePermission`'s
      `EmptyState` — never a redirect — and the test also asserts the screen handles the server's own refusal of a
      write, because the claim list from `GET /me` can be minutes old.
- [ ] **Exception path:** a published or retired version offers no editing control at all; the screen says that a
      change is a new version cloned from it, and the clone control on the register is the way out.
- [ ] **Offline:** every write control renders `OfflineBlockedAction` — "Needs connection — this will not be
      queued", word for word — because a billing write is never queued.
- [ ] A rate is entered and displayed as a percentage, never as a fraction, through the shared formatters
      (`docs/architecture/conventions.md` section 1.1), and no rate is pre-filled by the client.
