Sub-issue of #60. The "monitored" word in the parent's first acceptance criterion, and its fourth implementation
step: "monitor backup age/completeness/failures and test alerting". This is the only slice of #60 that changes code
under `src/`, which is why it is its own child — it is a platform health check and a metric, reviewed by the backend
reviewer, not a container or a document. The signal does not exist and nothing can read it:
`grep -rni "pg_stat_archiver\|backup" src/ --include=*.cs` finds one thing only, the doc comment on
`PlatformPermissions.HealthRead` (`src/Platform/Tailor360.Platform.Security/Permissions/PlatformPermissions.cs:49`)
promising a health report "including backup age and provider state" — a permission that is declared, granted to two
roles and reports nothing of the kind. Two other issues are waiting on this slice by name: #58's detailed-health
child says "Backup-age and WAL-freshness checks — **#60**, which supplies the scheduler metric this endpoint will
later report", and its alerting child says the WAL-freshness and backup-age alert rules are "written against #60's
metric names either way".

## Scope

- [ ] `src/Platform/Tailor360.Platform.Persistence/Health/BackupFreshnessHealthCheck.cs` — one `IHealthCheck`
      answering two questions from two sources: **WAL freshness** from
      `SELECT last_archived_time, last_archived_wal, last_failed_time, last_failed_wal, failed_count FROM
      pg_stat_archiver` on `PlatformDbContext`'s connection, and **base-backup freshness** from the status document
      at the configured path. Result mapping: `Healthy` when both are within their configured windows;
      `Degraded` when either is outside its window, or when `failed_count` has risen, or when the status document is
      older than its window; `Degraded` — never `Unhealthy` — when a source is unreadable, because an unreadable
      status file must not remove an instance from rotation. Every message names **which** signal is stale and by
      how long, and names no host, no path and no credential. `IClock` for every age.
- [ ] `Health/BackupMonitoringOptions.cs` — `SectionName = "BackupMonitoring"`, bound and validated in
      `PlatformServiceCollectionExtensions` beside the other four options types: `StatusDocumentPath` (null by
      default, meaning "no scheduler in this deployment" — see the next bullet), `WalArchiveMaximumAge` and
      `BaseBackupMaximumAge` with `[Range(typeof(TimeSpan), …)]` and **defaults taken from
      `docs/nfr/security-operations-targets.md` line 273 with that line cited in the XML comment**, and
      `StatusDocumentMaximumAge`. No figure is invented: each default quotes its document.
- [ ] **The "not configured" state is explicit and healthy.** With `StatusDocumentPath` unset — every developer
      machine, every integration test, the web host before a scheduler exists — the check returns `Healthy` with the
      description "backup monitoring is not configured in this deployment", and the WAL half still reports if
      `archive_mode` is on. A check that is red on every laptop is a check everyone learns to ignore.
- [ ] Registration in `src/Platform/Tailor360.Platform.Persistence/PlatformServiceCollectionExtensions.cs`:
      `.AddCheck<BackupFreshnessHealthCheck>("backups", tags: [HealthCheckTags.NonEssential])` and the options

- [ ] **The reading, behind a port, so no new project reference is needed.**

      `Tailor360Diagnostics.Meter` today, and adding that reference to publish one gauge is a platform coupling much
      harder to remove than to avoid. So: declare `IBackupSignalSource` in
      `src/Platform/Tailor360.Platform.Abstractions/Ports/`, returning the ages and the failure count as plain values;
      implement it in Persistence beside the health check, which uses it too; and register the instruments in

      `Telemetry/ObservabilityServiceCollectionExtensions.cs:82` (the meter itself is added to the provider at line

- [ ] **The lifetime of that port, which is the one thing most likely to fail review on this slice.** An
      `ObservableGauge` callback is invoked by the metrics SDK at *collection* time, on a background thread, with no
      request and **no DI scope**. The `sp` handed to `ConfigureOpenTelemetryMeterProvider` is the root provider, so
      an `IBackupSignalSource` whose implementation takes the **scoped** `PlatformDbContext` and is resolved there is a
      captive dependency: it either throws on resolution or silently holds one context for the life of the process and
      reads `pg_stat_archiver` on a disposed or cross-thread connection. Write it instead as:
      a **singleton** `IBackupSignalSource` that takes `IServiceScopeFactory`, creates a scope per read, resolves
      `PlatformDbContext` inside it, and **caches the last reading behind a minimum refresh interval** (an options
      property with a default, so a scrape every fifteen seconds does not mean a database round trip every fifteen
      seconds, and twelve gauge callbacks in one collection cycle mean one read). The health check resolves the same
      singleton, so the probe and the gauges never disagree about the numbers they are reporting.
      `IServiceScopeFactory` is the framework's own type and is **not** `IWorkerScopeFactory`, so **ARCH-020 is not
      engaged** — say that in one line in the pull request, because "a singleton creating scopes in the web host" is
      the shape ARCH-020 exists to catch and this is not an instance of it. The unit tests exercise the caching with a
      fake clock, which is the second reason every age comes from `IClock`.
- [ ] `src/Platform/Tailor360.Platform.Observability/Telemetry/BackupFreshnessMetrics.cs` — observable gauges on

      `tailor360.backup.wal_archive_age` (seconds), `tailor360.backup.base_backup_age` (seconds),
      `tailor360.backup.archive_failures` (counter value as reported by `pg_stat_archiver`), and

- [ ] `docs/platform/backups.md` — the monitoring section: the two signals, their sources, the four instrument names,

## Acceptance criteria

- [ ] With `archive_mode=on` and a fresh WAL archive, the check reports `Healthy` and the
      `tailor360.backup.wal_archive_age` gauge reports a value in seconds that tracks `pg_stat_archiver`.
- [ ] With a status document whose `lastSuccessAt` is older than `BaseBackupMaximumAge`, the check reports
      `Degraded` with a description naming the base-backup signal and its age, and
      `tailor360.backup.base_backup_age` reports that age.
- [ ] **Negative — a stale backup never removes an instance from rotation:** with both signals stale,
      `GET /health/ready` and `GET /health/live` still answer 200, because the check carries only
      `HealthCheckTags.NonEssential`. Asserted over the composed application, not by reading the registration.
- [ ] **Negative — an unreadable or absent status document degrades rather than fails:** with
      `StatusDocumentPath` pointing at a missing file, or at a file that is not the expected shape, the check is
      `Degraded`, the message names the signal, and nothing throws. With the path **unset**, the check is `Healthy`
      and says monitoring is not configured.
- [ ] **Negative — archiving failures are visible:** with `pg_stat_archiver.failed_count` non-zero and
      `last_failed_time` more recent than `last_archived_time`, the check is `Degraded` and
      `tailor360.backup.archive_failures` reports the count, because "WAL archiving is failing" and "WAL archiving is
      old" are different faults with the same symptom.
- [ ] **Exception — no clock call of its own:** `./scripts/dev test architecture` passes, which includes
      `SourceConventionTests` asserting ARCH-014 and ARCH-015 over `src/`; every age is computed from `IClock` and
      the unit tests set the clock rather than waiting.
- [ ] **Exception — no secret and no path in the signal:** the gauge attributes are the stanza name only, and the
      health description contains no file path, host, bucket or credential. Asserted in a unit test over the
      description text, because this is the rule a future edit is most likely to break.
- [ ] `ComposeConfigurationTests` passes with the new `BackupMonitoring__StatusDocumentPath` key, which is the
      assertion that the options type and the compose key agree.
- [ ] `dotnet format --verify-no-changes` is clean and the per-project coverage floor (`scripts/coverage-floor.py`,
      enforced in CI) is not lowered.
