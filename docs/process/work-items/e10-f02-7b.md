Sub-issue of #45. E10-F02-7a built the client reporting area and the `/reports` hub; this slice builds the owner and
manager **pipeline dashboard** and the drill list behind it, over E10-F02-2's four reads. There **is** a designed
prototype — `clients/pwa/src/stories/journeys/OwnerDashboard.tsx`, **360 lines**, with its own accessibility record
**`A11Y-RJ-08`** in `docs/nfr/a11y-checklist.md` section 6.8 (the record begins at line 969) — and it runs entirely on
`useState` over fixtures. This slice turns the pipeline half of it into real screens.

## What is already built (do not re-build)

  particular: the bar chart is an `aria-hidden` SVG whose rectangles are sized **by attributes, never by an inline
  style, because the content security policy forbids inline styles**; the `DataTable` underneath "is not a fallback
  tucked behind a disclosure: it is the data, it is always rendered, its scroll region is focusable, and the drawing
  is decoration over it"; a figure the role may not read is a **state**, not an error; and the dashboard **holds

## Acceptance criteria

- [ ] An Owner opens the pipeline dashboard from the hub and reads the tiles, the phase table and the trend, with the
      data-as-of and reconciliation state from the status strip visible on the screen (**A11Y-RJ-08** steps 1, 2, 3
      and 7).
- [ ] The chart's data **is** in the table, the table is always rendered, its scroll region is focusable, and the SVG
      is `aria-hidden` with its rectangles sized by attributes — asserted by a test, because it is both the prototype's
      stated rule and the content security policy's.
- [ ] Filtering announces the filter set and the result count **once**, through `Filters`, and the applied chips remove
      individually and clear as a set.
- [ ] The **active / closed** control changes the population and says which one is shown; neither answer mixes them.
- [ ] Drill-through: a row opens the garment's job card for a caller holding `orders.read`; for a caller without it the
      row renders as text with no link and no error.
- [ ] The drill list's filters round-trip through the query string, so a pasted link reproduces the same view.
- [ ] **Negative — forbidden:** a Tailor reaching `/reports/pipeline` sees the `RequirePermission` empty state with
      `admin.forbidden.title` / `admin.forbidden.body`, is **not** redirected, and the shell's navigation still works.
- [ ] **Negative — the read fails:** a `500` renders `AuthProblemAlert` in plain language with a retry that reuses the
      same request, and never the problem's code or a stack trace.
- [ ] **Negative — offline:** with the network down the screen says so through the shell's banner and offers retry; it
      does not queue anything and does not show a stale figure as if it were current.
- [ ] **Negative — a narrowed answer:** when the server reports it covered fewer branches than were asked for, the
      screen says which branches the figures cover, so a narrowed answer can never be mistaken for the whole shop.
- [ ] **Exception — an empty shop:** zeroed tiles and an empty table with the as-of line, never a 404-looking screen.
- [ ] **Exception — the horizon is unset:** with `Reporting:Pipeline:DueSoonHorizonDays` unconfigured the server omits
      the due-soon bucket, and the screen omits the tile and says the horizon is not configured — it does not render
      zero and it does not invent a number. A test asserts it.
- [ ] **Exception — the dashboard holds still:** nothing re-orders or refreshes under the reader's hands; an update
      that has arrived is offered behind a control (**A11Y-RJ-08** step 8, WCAG 2.2.2), and a test asserts no interval
      is started.
- [ ] No horizontal page scroll at any of the five default widths at 100% and 200% zoom, and no axe violation, on
      either screen.
