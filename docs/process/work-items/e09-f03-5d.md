| Screen | `path` / `at` for `withBillingApi` | Routes to stub |

| Reconciliation approval | `/billing/cashier-sessions/:sessionId/reconciliation` / `/billing/cashier-sessions/<CASHIER_SESSION_ID>/reconciliation` | `GET /api/v1/billing/cashier-sessions/<CASHIER_SESSION_ID>/reconciliation`, `POST /api/v1/billing/cashier-sessions/<CASHIER_SESSION_ID>/reconciliation/approve` |
| Dispatch exception approval | `/billing/dispatch-exceptions/new` / `/billing/dispatch-exceptions/new?orderId=<ORDER_ID>` | `GET /api/v1/billing/orders/<ORDER_ID>/dispatch-exception-balance`, `POST /api/v1/billing/dispatch-exceptions` |

Three traps, each confirmed by reading the screens:

1. `ReconciliationApprovalRoute` reads the session through `getCashierSessionForReconciliation`, which is `GET
   …/cashier-sessions/{id}/reconciliation` — the narrow read added under `payments.approve_reconciliation` for #220,
   **not** `GET …/cashier-sessions/{id}`. Stubbing the wrong one gives `story.route-not-stubbed`.
2. Its **empty** state is `batch === null || batch.approvedAt !== null` (line 101): a session whose batch needs no
   approval, or whose batch is already approved, renders "approval not required". The loaded state therefore needs
   `aCashierSession({ status: 'Closed', reconciliationBatch: aReconciliationBatch() })` — a `PendingApproval` batch with
   `approvedAt: null`.
3. `DispatchExceptionApprovalRoute` takes `orderId` from the query string into component state (line 60) and only shows
   the balance when `balance.value.orderId === orderId` (line 74), so the empty state is simply no `orderId` on the
   address and the loaded state needs `anOrderBalance({ orderId: ORDER_ID })` with the identifier matching.
