Sub-issue of #51. The queue of #E12-F02-4 is invisible, and an invisible queue is the failure this whole feature
exists to prevent: `clients/pwa/src/components/states/useNetworkState.ts` states it outright — treating
`onLine === true` as a promise "would produce the worst failure this product can have on a counter: an action that
looks queued and never arrives". This sub-issue builds the **always-on half** of the answer: the shell region that
says what is waiting on every screen, the inline marker a feature row carries, and the pending count in the update
prompt. The `/sync` screen, the eviction notice and the sign-out gate are **#E12-F02-5b**.

**Why this is separate from the screen.** The sync channel in `clients/pwa/src/components/layout/shellStatus.ts` was
built for exactly this and says so: "The offline queue itself is #51's; this is the region it will publish into." That
is a publisher, a hook, one small marker and one prop — a few hundred lines. The `/sync` screen is a route with three
sections, a confirm-with-reason action and its own story set, and the calibration in this repository is unambiguous:
`clients/pwa/src/routes/catalog/CatalogVersionEditorRoute.tsx` is 978 production lines for **one** route before its
entry components, its API module, its messages and its stories. Putting a route and four components in one pull
request is how a session runs out of context at the point where the accessibility evidence is produced.

## Scope

- [ ] **`clients/pwa/src/offline/useQueueState.ts`** — `useSyncExternalStore` over `queueState`'s snapshot and
      `subscribe`, in the shape `useNetworkState` already uses, so there is no effect-driven `setState` cascade. One
      hook, no derived state that the store could hold itself.
- [ ] **`clients/pwa/src/offline/SyncStatusPublisher.tsx`** — a render-nothing component mounted once in
      `clients/pwa/src/components/layout/AppShell.tsx`, inside `ShellStatusProvider`, which maps `queueState` onto
      `announceSync`. One message at a time, superseding rather than stacking, because the channel holds exactly one
      (**A11Y-43**). The mapping, in priority order, and each message says what to do next rather than only what is
      true:
      - `full` → **assertive**: the queue is at its bound and further work will not be queued (**A11Y-OF-04**).
      - `conflict` / `paused` → **assertive**: *needs your attention*, naming the operation and the job number of the
        paused entry (**A11Y-OF-07** requires the conflict to be named by what it was and which job it belongs to).
      - `cannotSend` non-empty → **assertive**: this device cannot send *n* items.
      - `sending` → **polite**: sending.
      - `lastDrain` present and `pending` zero → **polite**: *n sent, n need your attention* — the reconnect outcome
        **A11Y-OF-06** asks for, "otherwise the person cannot know whether their morning's scans landed". It
        supersedes, and is cleared when the next drain starts; **no timer** dismisses it, because the region is
        non-dismissable by rule and a timed clear is a toast wearing a region's clothes.
      - `pending` greater than zero → **polite**: *n waiting to send* (**A11Y-OF-03**, which also asks that the count
        stay visible).
      - otherwise → `announceSync(null)`.
      Each message's text carries a link to `/sync`, the screen **#E12-F02-5b** adds. Until that child merges the link
      target does not exist: render the message **without** the link in this pull request and add the link in
      #E12-F02-5b, or the criteria here cannot be verified on their own. Say which you did.
- [ ] **`clients/pwa/src/offline/NotYetSentMarker.tsx`** — the small inline component a feature screen puts beside a
      row it has queued: *not yet sent*, with the queued time. It takes the entry from `useQueueState`, and it is icon
      **and** text, never colour alone. **It takes the sentence as a required message id prop** and hard-codes none:
      #48's `e11-f02-8b` needs "delivered — not yet synced" (the wording `docs/architecture/failure-modes.md` section
      9 line 196 and plan line 2178 both fix), #36's scan screen needs "not yet sent", and neither side should own the
      other's wording. A test asserts the component cannot render without a sentence.
- [ ] **The pending count in the update prompt** — pass `pendingCount` from `useQueueState` into
      `clients/pwa/src/offline/UpdatePrompt.tsx` where it is mounted in `AppShell`, and extend the `available` wording
      to say how many items are waiting and that they stay on the device through the reload. The reload stays behind
      the same explicit consent #E12-F02-2 established; this issue adds a sentence, not a new gate. The `required`
      form is unchanged: an incompatible client cannot send anyway, and delaying a required update to protect a queue
      it cannot drain would strand the person twice.
- [ ] **Messages** extended in `clients/pwa/src/i18n/messages/offline.ts` in **both** languages. Every count uses an
      ICU plural; no sentence is built by concatenation, because word order differs in Tamil (the rules at the top of
      `clients/pwa/src/i18n/messages/shell.ts`). Untranslated Tamil carries the English text and the
      `// not translated — awaiting native-speaker review` comment. Queued times are formatted through `getFormatters`
      from `clients/pwa/src/i18n/formatters.ts` (`DEFAULT_TIME_ZONE = 'Asia/Kolkata'`), never a direct `Intl` call.
- [ ] **Stories** in `clients/pwa/src/offline/syncStatus.stories.tsx` — component stories, not route stories, so
      `renderWithProviders`-style wrapping is enough and no `withAdminApi` is needed: waiting, sending, drain
      outcome, paused conflict, cannot-send, queue-full, and the marker in both its sentences, each also in the
      pseudo-locale (`clients/pwa/src/i18n/pseudo.ts`, `PSEUDO_LOCALE = 'en-XA'`, `PSEUDO_GROWTH_FACTOR = 1.4`). Do
      **not** use `JourneyFrame` from `clients/pwa/src/stories/journeys/journeys.stories.tsx`: it wraps children in
      its own `MemoryRouter` and cannot be combined with the admin transport harness.

## Acceptance criteria

- [ ] With items queued through a fixture operation, the sync region states how many are waiting on **every** screen,
      in the same place, and stays until the state changes — it is never a toast and it has no dismiss control
      (**A11Y-OF-03**, **A11Y-42**).
- [ ] When a drain finishes, the region states the outcome — how many were sent and how many need attention — and
      that message is superseded by the next state rather than removed on a timer (**A11Y-OF-06**).
- [ ] **Negative — one message, not a stack:** with the queue full *and* a conflict *and* items waiting, exactly one
      message is published, the most urgent one, and a test asserts the region's content rather than the call count
      (**A11Y-43**).
- [ ] **Negative — nothing pending, nothing said:** with an empty queue and no `lastDrain`, `announceSync(null)` is
      called and the region renders nothing. A publisher that announces "0 waiting" is a publisher people learn to
      ignore.
- [ ] **Negative — the marker cannot be vague:** `NotYetSentMarker` does not compile without a sentence message id,
      and a test asserts the rendered accessible text is the caller's sentence and not a default. A queued delivery
      confirmation must never read as "delivered".
- [ ] **Negative — the update prompt does not change its gate:** with items pending, the `available` prompt states the
      count and still requires explicit consent to reload; declining leaves the build, the queue and the region
      exactly as they were. The `required` prompt is unchanged by this issue, and a test asserts that.
- [ ] **Exception — the conflict is named:** the paused message names the operation and the job number of the paused
      entry, never a status code (**A11Y-OF-07**: "a conflict named 'error 409' is not resolvable at a counter").
- [ ] **Exception — no queue at all:** with `queueState` reporting an empty queue because the store is unavailable,
      nothing is published, nothing is rendered, and no error reaches the user.
- [ ] Accessibility: `expectNoAccessibilityViolations` from `clients/pwa/src/design-system/testing/axe.ts` on each
      component; no horizontal overflow and no obscured focus through
      `clients/pwa/src/design-system/testing/expectNoHorizontalOverflow.ts` **at its own defaults** (320, 360, 768,
      1024 and 1280 px at 100% and 200% zoom — do not narrow the list), with the region occupied, at phone width where
      the bottom navigation and the virtual keyboard compete for the space; status by icon and words, never colour
      alone.
