automate. `src/Tools/Tailor360.Cli/Commands/SeedSyntheticCommand.cs` is 156 lines that write two branches and one

added by their own issues". There is no staff account, therefore no session, therefore no journey. #52's second
implementation step asks for the Playwright projects **"and deterministic synthetic data"**, and the plan's #52

## What is missing, and the trap that makes this a sub-issue of its own

- **No staff account.** `seed-synthetic` writes branches and a flag and nothing else.
- **The command-line tool has the wrong data-protection key ring.** `grep -rn "AddTailor360DataProtection" src/`
  returns exactly one call site: `src/Hosts/Tailor360.Web/Program.cs` line 82. `CliHost.Build()` does **not** call
  it, and Identity's own `AddIdentityModule` calls a bare `services.AddDataProtection()`
  (`IdentityModuleServiceCollectionExtensions.cs` line 234) with `TryAddSingleton` for the protector. So a TOTP
  secret protected by `seed-synthetic` today is wrapped by a **different application name and a different key
  ring** from the one the web host holds, and `ISecretProtector.Unprotect` in the web host returns a failure — the
  account is told to re-enrol and the second factor can never be answered. This is silent: the command succeeds,
  the row is written, and only the sign-in fails. Fixing it is one line in `CliHost` and is in scope here.
- **A confirmed enrolment can refuse the suite's first code as a replay.** `TotpEnrolment.Confirm(acceptedStep,
  now)` sets `LastAcceptedStep`, and the type's own remark is that "a code from this step or an earlier one is a
  replay and is refused however valid it would otherwise look". Confirming with the step of `clock.UtcNow` means a
  suite that signs in within the same 30-second window is refused. Confirm with the step computed from
  `clock.UtcNow - 2 minutes` instead, and say so in a comment.

## Before a session starts: one blocking pre-flight check

It is not a judgement call and may not be made mid-flight. Run, from a clean checkout against a development
database:

```
DOTNET_ENVIRONMENT=Development dotnet run --project src/Tools/Tailor360.Cli -- seed-synthetic
```

**#214 says this currently fails**: `CliHost` registers neither the Integration module (which owns `IPdfRenderer`)
nor the full security stack (which owns `ICurrentUser`), both of which Billing's handlers resolve, so the container
fails to build whenever the environment is Development — and `seed-synthetic` cannot be run in any other
environment, because `CliHost.ResolveEnvironmentName()` (line 97) falls back to `Environments.Production` and
`EnvironmentGuard` refuses there with exit code 3. If the command fails as **#214** describes, **this sub-issue is
blocked and #214 is fixed first**. Do not work around it by relaxing the guard, by adding an override flag, or by
seeding from a test project.

      shared between the tool and the host.
- [ ] **Negative:** with `TAILOR360_SEED_PASSWORD` unset the command fails, names the variable, and writes no
      account. A `grep -rn` for the seeded password over the repository finds no literal.
- [ ] **Negative:** with the environment resolving to Production the command exits 3 and writes nothing, and the
      message is `EnvironmentGuard`'s, not a new one.
- [ ] **Negative:** the first valid code after seeding is accepted rather than refused as a replay — asserted by
      confirming an enrolment and immediately answering a challenge in the same 30-second window.
- [ ] **Exception:** an account that already exists from a previous run is not duplicated and its password is not
      silently rotated; the command says which accounts it found and which it created.
