## How an endpoint is declared in this repository

There is one accepted shape and it is not optional. Copy it from
`src/Modules/Billing/Tailor360.Modules.Billing.Api/Invoicing/InvoiceEndpoints.cs` (a write at lines 190-196, a read
at 139-141), which is the closest merged example:

```
    .RequirePermission(<PermissionKey>, BranchScope.CurrentBranch)   // ARCH-007
    .ScopedToResource(<ResourceKinds.Thing>, "<routeValueName>")     // ARCH-023, when the route names a row
    .RequireRateLimiting(RateLimitPolicyNames.Write)                 // ARCH-017, exactly one
    .Audited(<Handler>.<Something>Action, reasonRequired: true)      // ARCH-008, every write
    .RequireIdempotency()                                            // where a client may retry
    .RequireIfMatch()                                                // where the row carries an ETag
    .WithRequestTimeout(RequestTimeoutPolicies.Command)               // every endpoint in the repository has one
```

- Verbs: `Platform.Security/Endpoints/EndpointAuthorisationExtensions.cs` (`RequirePermission(key, scope)`,
  `Audited(action, reasonRequired)`, `AllowAnonymousWithJustification`);
  `ResourceScopeEndpointExtensions.cs` (`ScopedToResource(resourceKind, routeValueName, scope)`, and the
  deliberately noisy exemption verb for a route whose identifier names nothing branch-owned);
  `RequestSafetyEndpointExtensions.cs` (`RequireIdempotency`, `RequireIfMatch`);
  `StepUpEndpointExtensions.cs` (`RequireStepUp`).
- **Rate-limit policies**, all of them, from `Platform.Security/Endpoints/RateLimitPolicyNames.cs`:
  `DefaultUser` = `default-user` (ordinary authenticated read), `Write` = `write` (authenticated state change),
  `ScanBurst` = `scan-burst`, `ExportHeavy` = `export-heavy`, plus `AuthenticationAnonymous`,
  `MultiFactorChallenge`, `RecoveryAnonymous`, `DefaultIp`. There is no other policy, and inventing one is a
  change to the limiter configuration in the web host.
- **Request timeouts**: `Platform.Security/Endpoints/RequestTimeoutPolicies.cs` — `Read` = `read`,
  `Command` = `command`, `Report` = `report`, `Export` = `export`. **Every** endpoint in `src/Modules/` carries one

- **Branch scopes** from `Platform.Abstractions/Multitenancy/BranchScope.cs`: `CurrentBranch` (the default),
  `AssignedBranches`, `Organisation`, and the member that demands no branch reach at all.

## Acceptance criteria

- [ ] A Branch Manager holds a job in production with a configured reason code and a reason, resumes it, and
      reschedules its promised date; each act leaves a history row, publishes its existing event, and writes its
      audit action, and the job's previous due date remains readable on its history.
- [ ] Cancelling a job and cancelling a whole order each work over HTTP on an order with no recognised charge, and
      both events carry the billing adjustment intent as optional event data.
- [ ] Every route declares a permission, one rate-limit policy, the audit filter and a resource scope
      (ARCH-007/008/017/023), and the endpoint-inventory contract test shows it.
- [ ] **Negative**: cancellation is refused while Billing reports a recognised charge or money taken, and the
      refusal **names the financial arm** and the order balance that blocked it — not "cancellation failed"; a
      caller without `orders.cancel_job` receives `403` `security.forbidden`; a caller whose branch does not reach
      the order receives the same answer as for an order that does not exist; a command with no reason is refused by
      validation, because `orders.hold`, `orders.resume`, `orders.reschedule`, `orders.cancel` and
      `orders.cancel_job` all carry `RequiresReason: true`; a replayed `Idempotency-Key` returns the first outcome;
      a stale `If-Match` is refused `412`.
- [ ] **Negative, visibly incomplete**: the response to both cancellations records `CustodyNotEvaluated` and
      `StockNotEvaluated` in its guard result, and an integration test asserts that **both appear** — so that a later
      session cannot quietly drop an arm and still pass. A cancellation that the financial arm permits is therefore
      permitted with two arms unevaluated, which is the state of the world until E06-F03-5 and #39, and the pull
      request says so as a known limitation rather than implying the guard is complete.
- [ ] **Exception**: resuming a hold that is already resolved is refused rather than writing a second resolution;
      holding a job that is already on hold is refused with the existing Domain error; a cancelled job cannot be
      held, resumed or rescheduled (`orders.job-status-transition-not-allowed`).
