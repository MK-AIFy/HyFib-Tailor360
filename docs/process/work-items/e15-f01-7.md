## Scope

- [ ] `infra/ansible/` — a playbook and a small number of roles that take a host with a supported operating system
      and a reachable package source to a running stack, with **no manual step**: install and enable the container
      runtime; create the service account and the `${TAILOR360_STAGING_SECRETS_DIR}` tree with the modes
      `docs/platform/secrets.md` requires; render `.env` from `infra/compose/.env.example`'s variable set; place the
      repository checkout; install `scripts/tailor360-deploy`; cap the host's own logs; and run the deployment
      script for the digests it is given. **The firewall role is E15-F01-7b's**; this playbook leaves the role slot and
      the variable for it and says so.
- [ ] An inventory **template** with a documented variable list, and **no host, no address, no credential and no
      provider** committed. Secret **values** are never rendered by the playbook — it creates the files' locations and

      already uses. CLAUDE.md section 4 rule 6 and `docs/platform/secrets.md` are the rules; `infra/CLAUDE.md` section
      3 is the local statement of them.
- [ ] Idempotence: running the playbook twice changes nothing on the second run, asserted by the run's own change

## Acceptance criteria

- [ ] From an empty host, one playbook run produces a stack in which `GET /api/version` answers with the expected
      version and `environment`, and `/health/ready` is healthy — with no command run outside the playbook. Asserted
      in CI against an ephemeral host.
- [ ] A second run of the same playbook reports zero changes.
- [ ] Every secret file the compose stack requires is created with the expected owner and mode, and **no secret value
      is written by the playbook**; a missing required secret file fails the run with a message naming the file.
      Proved by a run against a host whose secret directory is empty.
- [ ] The compose stack the playbook starts publishes exactly the one port the file declares — read back from
      `docker compose ps` and from the rendered `.env`'s `TAILOR360_BIND_ADDRESS`, which is what this playbook
      controls. **The host-level firewall and the from-outside reachability check are E15-F01-7b's**, and this pull
      request must not claim them.
- [ ] **Negative:** a playbook run with a required variable unset fails before it changes anything on the host, naming
      the variable. It does not substitute a default for an address, a digest or a secret path.
- [ ] **Negative:** a playbook run whose image digests do not verify fails through `scripts/tailor360-deploy`'s own
      refusal, and the host is left with nothing pulled — the two components must not each have their own opinion about
      verification.
- [ ] **Negative:** the provisioning test fails when a manual step is needed — for example when a role silently
      depends on a file a person would have placed. Demonstrated by removing such a file and showing the run fail
      rather than skip.
- [ ] **Exception:** a run against a host that is **already** provisioned and serving upgrades it to the given digests
      without destroying its volumes. A provisioning playbook that can only build from empty is a reinstaller, and
      `docs/dev/staging.md` rule 4 reserves `down -v` for the failed-migration reset alone.
- [ ] `./scripts/dev docs` passes and the commands of `infra/CLAUDE.md` section 7 pass in the new job.
- [ ] **The toolchain is new to this repository and is pinned like every other one.** `ls infra/` has no `ansible/`,
      `./scripts/dev doctor` knows nothing about Ansible, and `.github/dependabot.yml` has no ecosystem that would
      raise it. So: pin the Ansible version the CI job installs, exactly as the job pins `syft-version` and the Trivy
      action; run `ansible-lint` in the same job with its own pinned version; and **do not extend `scripts/dev` or
      `dev.ps1`** — they deliberately wrap nothing that is already a one-liner (CLAUDE.md section 2), and a new verb
      is a separate decision. Say in one line whether a `dependabot.yml` ecosystem row is worth adding, and if so
      leave it to whoever owns that file next rather than editing it here.
