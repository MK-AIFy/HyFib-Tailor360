Two traps, both confirmed by reading the screens:

1. `CashierSessionRoute` picks the caller's own session with `openSessions.value?.find((session) => session.cashierId
   === currentUser.userId)` (line 74). `aCashierSession()` defaults `cashierId` to `CASHIER_ID` while
   `STORY_USER.userId` is a different synthetic identifier, so an "open session" story that does not reconcile the two
   silently renders the **no open session** branch. Pass `aCashierSession({ cashierId: STORY_USER.userId })`.
2. `withAdminApi` matches a stub by the exact `"METHOD /path"` string including the query, and answers anything else
   with `storyProblem(404, 'story.route-not-stubbed')`. The cashier list is read as `?status=Open`, capital O.
