## Scope

- [ ] **`GET /api/v1/reporting/quality`** — rates with their denominators, **never bare percentages**: first-pass
      rate, QC failure rate, rework rate, rework cycles per reworked garment and alteration rate, by branch,
      category and service type over a period, **each row carrying the numerator, the denominator and the excluded
      counts** so a figure can never be read without the population it came from.
- [ ] **`GET /api/v1/reporting/quality/reasons`** — failure reason codes ordered by frequency with each one's share
      of the period's failures, by phase and category, over a period, for "what actually goes wrong" rather than
      "who".
- [ ] **The denominator is `reached_qc = true`**, not every garment: a garment whose pinned workflow version has no
      QC phase is in the excluded count and in neither rate. A period with no QC at all answers **"no data"** and
      not `0%`, which is a distinct state in the payload and not a nullable number a client has to guess about.
- [ ] **No attribution to a named person anywhere.** Neither payload has a field for a user identifier, a display
      name or anything resolving to one, and a test asserts it over the payload types. Per-assignee figures live
      only behind `reports.read_workload` in E10-F02-3b.
- [ ] **No media.** No storage key, identifier or URL for a QC evidence photograph appears in either payload;
      evidence is streamed by Media's authorising endpoint (security rule 9) and is **Confidential** under 5.5.
- [ ] **Both routes declare** `RequirePermission(ReportingPermissions.Read, BranchScope.AssignedBranches)`
      (ARCH-007), exactly one rate-limit policy — `RateLimitPolicyNames.DefaultUser` (ARCH-017) — and
      `RequestTimeoutPolicies.Report`. **No `.Audited(...)`**: with no personal data in either payload the read is
      not itself sensitive (CLAUDE.md section 4 rule 5), which is the difference between this slice and E10-F02-3b.
      Neither route carries a route parameter, so ARCH-023 needs no resource scope.
- [ ] **Payload types in the `Api` project** (ARCH-013 — no `Domain` type is ever returned), under
      `…Reporting.Api/Payloads/`. **No response view**, because every field is `Operational` and nothing is gated on
      a second permission.
- [ ] **Configuration, not code** (DOR-11): the period bucket sizes are `Day`, `Week` and `Month` in the branch
      timezone, matching the convention E10-F02-2 introduced; the rounding rule for a share is stated in the
      dictionary and applied in one place.
- [ ] **One row per route in the `<!-- matrix:endpoints -->` block** plus the matching fixtures in `matrix.yaml`;
      regenerate `docs/api/openapi.v1.json` then `clients/pwa/src/api/schema.d.ts`
      (`pnpm --dir clients/pwa generate:api`, `generate:api:check` clean afterwards).
- [ ] **Metric dictionary**: extend E10-F02-4a's six entries with the grouping keys, the bucket semantics, the
      "no data" rule and the rounding rule these two routes apply.
- [ ] **No migration.** This slice reads what E10-F02-4a created.

## Acceptance criteria

- [ ] A Branch Manager holding `reports.read` reads both routes over HTTP against projections filled by
      E10-F02-4a's stream and receives only their own assigned branches' figures, with the period and the `asOf`
      instant stated in each response.
- [ ] `GET /api/v1/reporting/quality` reports the first-pass rate with its numerator and denominator, and the
      denominator counts garments that reached QC — a garment whose workflow version has no QC phase is in the
      excluded count and in neither rate.
- [ ] `GET /api/v1/reporting/quality/reasons` orders reason codes by frequency with each one's share of the period's
      failures, and the shares sum to 100% within the stated rounding.
- [ ] **Negative — another branch:** a caller assigned to branch A receives no branch-B row, by filter or otherwise,
      and the response states the branches it covered. Not an error: the filter is intersected with
      `AssignedBranches`.
- [ ] **Negative — no permission:** a Tailor without `reports.read` is answered `403` `security.forbidden`
      (`AuthorisationProblemResultHandler.ForbiddenCode`), per the `not-permitted` answer in `matrix.yaml`.
- [ ] **Negative — no person is nameable:** a test asserts neither payload type has any property resolving to a user
      identifier or a display name. This is a test because it is the parent's "avoid misleading staff ranking"
      criterion, and a prose promise cannot fail a build.
- [ ] **Negative — a malformed filter:** an unknown phase code, a reversed date range or a limit above the cap is
      answered with RFC 9457 problem details naming the field, never a stack trace and never a silently clamped
      range; the limit is clamped as `ListInvoices` clamps it and the response states the limit applied.
- [ ] **Exception — a zero denominator:** a period in which nothing reached QC answers "no data" for every rate, with
      the excluded count explaining why, and never `0%`.
- [ ] **Exception — an unknown reason code:** a code outside the current vocabulary appears under its own value with
      its share, because **OD-10** is open and the read maps nothing.
- [ ] **Rule-level:** both routes declare a permission (ARCH-007) and exactly one rate-limit policy (ARCH-017); no
      field of either payload is classified above Internal, which is why neither is audited; the contract tier proves
      all three.
