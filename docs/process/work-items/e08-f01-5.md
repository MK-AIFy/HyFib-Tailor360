## Acceptance criteria

- [ ] An Inventory Clerk holding `inventory.manage_locations` creates a location with two allowed transfer
      destinations, edits it, deactivates it and reactivates it from the screen — proved by a Vitest journey
      against the stubbed transport, with no direct database access and no deployment in between. This is the
      location half of #38 acceptance criterion 1.
- [ ] Both routes this child adds are guarded by `RequirePermission` on exactly one key, and a caller without the
      key sees the sentence and who to ask — **never a redirect** and never a list of controls that all refuse.
- [ ] A duplicate location code is shown as a field-level error on the code field, taken from the server's RFC 9457
      problem through `plainLanguageDetail`, with the typed input intact — never a raw code and never a toast.
- [ ] A self-reference is not offered in the transfer-destination list, and a destination the server refuses as
      retired is rendered in the server's words beside the list, with the rest of the typed form intact.
- [ ] **Concurrency, verified against the stub rather than against a sibling.** When a stubbed read carries an
      `ETag`, the save sends the same value as `If-Match` (asserted from `RecordedCall`); a stubbed `409` carrying
      `currentVersion` shows what the record says now beside what the person typed, offers the choice, and a retry
      reuses the **same** `Idempotency-Key` (`docs/architecture/conventions.md` section 4.3). When a stubbed read
      carries no `ETag`, the save sends no `If-Match` and never produces a `428`.
- [ ] A retired location is still listed and still readable, and the screen offers reactivation instead of edit
      controls that would be refused — the client half of `docs/prd/configurable-vs-fixed.md` line 82.
- [ ] Offline, a read shows the last value with the network banner and a write is refused in place with
      `OfflineBlockedAction`; nothing is queued and nothing is silently lost.
- [ ] No user-facing literal anywhere in the new components: every string is an `inventory.*` message id, and
      `pnpm --dir clients/pwa typecheck` proves `ta-IN` carries every key.
