Sub-issue of #59. `docs/architecture/deployment.md` section 8 lists the rules "that do not vary by environment", and
rule 4 is the only one of the seven the document leaves unsettled, with the reconciliation assigned by name: "**Health
probes are internal.** The target is that only `/health/live` is reachable from outside; the interim baseline is
stricter, answering `404` to every `/health/**` path at the proxy, with external liveness checked through
`GET /api/version`. **Issue #59 reconciles the two.**" Rules 1 and 2 of the same section — "PostgreSQL, the object
storage and the malware scanner publish no port outside the internal network" and "The reverse proxy is the only
container with a published port" — are properties nothing enforces on a host: `docs/dev/ports.md` says what must be
reachable and what must not, and there is no firewall anywhere in the repository (`find infra -type f` returns thirteen
files, none of them a firewall rule, an nftables set or a systemd unit). This slice settles rule 4, writes the host
firewall baseline, and makes both observable from outside rather than asserted in a document.

It is deliberately separate from **E15-F01-7**, which builds the playbook. That child takes an empty host to a healthy
stack; this one decides and enforces what the host exposes. Splitting them keeps each within one session: the
provisioning child already carries six playbook runs, and applying and then asserting host-level packet filtering in an
ephemeral container needs its own set of decisions about what can honestly be proved where.

## What is already built (do not re-build)

- `infra/caddy/Caddyfile` — the proxy. Line 69 sets the `X-Robots-Tag` default; **lines 84-86** are the rule this slice
  changes, and the comment above them (lines 80-83) is the argument that has to be answered rather than deleted: "Health
  probes are internal. An orchestrator, the compose watchdog and `./scripts/dev status` call them on the container port;
  nothing outside the network has a reason to. The matcher names the bare path too: `/health/*` alone lets `/health`
  through to the application's shell fallback, which would answer a probe aimed at the wrong path with 200 and an HTML
  body." The matcher is `@health path /health /health/*` and the handler is `respond "Not found" 404`.
- `src/Platform/Tailor360.Platform.Observability/Health/HealthEndpointExtensions.cs` — `LivePath` `/health/live`,
  `ReadyPath` `/health/ready`, `StartupPath` `/health/startup`, each mapped by tag. **The application side does not
  change**: this is a proxy and a firewall decision, and the three probes keep their current semantics.
- `docs/dev/ports.md` — every port in every stack, what binds it and on which interface, with sections for development
  from the SDK, the built-image overlay, interim staging and tests, plus a "Changing a port" section. **This is the
  authority the firewall is generated from.** Do not write a second list.
- `infra/compose/docker-compose.staging.yml` — only the proxy publishes a port, on
  `${TAILOR360_BIND_ADDRESS:-127.0.0.1}`; every data service is on the `backend` network with no `ports:` entry. The
  compose file is already correct and **needs no change**. The firewall is the second layer, for the case where
  somebody adds a `ports:` entry or runs something outside compose.
- `docs/architecture/deployment.md` sections 3 and 4 — the two networks and the published-versus-internal port table,
  which rules 1 and 2 summarise.
- **E15-F01-7**'s `infra/ansible/` — the playbook, the roles layout and the inventory variable list. This slice adds one
  role to it and one variable group; it does not restructure either.
- `tests/Tailor360.ArchitectureTests/ComposeConfigurationTests.cs` — the pattern for asserting against the compose files
  from a test, with its negative controls in `NegativeControlTests.cs`. If any part of this rule turns out to be
  statically checkable (for example "no service but the proxy declares `ports:`"), this is where it goes, and it needs
  the next free `ARCH-nnn` and its rows — see Modules, contracts and events.

## What is missing

- The decision. Rule 4 has read "Issue #59 reconciles the two" since it was written, and the Caddyfile and the document
  therefore disagree by design.
- Any firewall. Nothing applies or checks a packet filter, so rules 1 and 2 hold only because the compose file happens
  to be written correctly.
- Any check from outside. No job and no script asks a provisioned host what it answers on a port, so "not reachable from
  another machine" is a claim nobody has tested.
