Sub-issue of #58. `/health/detail` is specified in four merged documents and built in none of them:
`docs/architecture/container.md` line 172 gives it its question, its checks and its access rule ("Internal network or
the `admin.health.read` permission only. Never exposed publicly"); ADR-0010 line 241 fixes its orchestrator-neutral
semantics; `docs/architecture/failure-modes.md` line 31 makes it the place every Degraded dependency is reported;
`docs/prd/raci.md` row 28 makes it how backup age is read. What exists is
`src/Platform/Tailor360.Platform.Observability/Health/HealthEndpointExtensions.cs`, which maps exactly three paths —
`LivePath`, `ReadyPath`, `StartupPath` — all with `.AllowAnonymous()`. Two already-open sub-issues depend on the gap:
#188 and #192 both assert behaviour "reported on `/health/detail` as Degraded". The permission this route needs already
exists and is already granted: `docs/security/permission-matrix.md` line 241 carries `admin.health.read` against issue
**#58**, to `owner` and `admin`.

## What is already built (do not re-build)

- `src/Platform/Tailor360.Platform.Observability/Health/HealthEndpointExtensions.cs` — the `Map` helper, the
  `HealthProbeMetadata` marker that the ARCH-007 test reads, the `ResultStatusCodes` map that answers 200 for `Degraded`
  and 503 for `Unhealthy`, and `.ExcludeFromDescription()`, which is why no health route appears in
  `docs/api/openapi.v1.json`. Extend this file; do not add a parallel mapper.
- `src/Platform/Tailor360.Platform.Observability/Health/HealthResponseWriter.cs` — writes `{Status, DurationMs,
  Components:[{Name,Status}]}` and deliberately discloses nothing else. The detail payload is a **second** writer beside
  it, not a change to this one: the anonymous probes must keep answering the minimal body.
- `src/Platform/Tailor360.Platform.Abstractions/Health/HealthCheckTags.cs` — `Live`, `Ready`, `Startup` and
  `NonEssential` (line 34). **`NonEssential` is carried by exactly two checks today** —
  `OutboxBacklogHealthCheck` and `AuditPartitionHealthCheck`, at
  `src/Platform/Tailor360.Platform.Persistence/PlatformServiceCollectionExtensions.cs:196-197` — and **no probe maps
  that tag**, so both run on every `/health/*` request and their result is read by nobody. That is the quiet half of
  this gap, and the detail endpoint is what makes them visible. The tag's documentation comment states the contract: a
  non-essential check reports `Degraded`, is visible on the diagnostics endpoint and alerts, and keeps readiness
  green.
- The checks to report, and **which host has which** — this is not the same list on both, and a test that asserts one
  list for both will fail:
  - Registered by `AddTailor360Platform()` and therefore present in **both** hosts:
    `DatabaseHealthCheck` (`ready`), `MigrationStateHealthCheck` (`startup`), `OutboxBacklogHealthCheck`
    (`non-essential`) and `AuditPartitionHealthCheck` (`non-essential`) —
    `src/Platform/Tailor360.Platform.Persistence/PlatformServiceCollectionExtensions.cs:193-197`, with the
    implementations in `Health/PlatformHealthChecks.cs` and `Health/AuditPartitionHealthCheck.cs`.
  - `DataProtectionKeyRingHealthCheck` (`startup`) — `DataProtection/DataProtectionServiceCollectionExtensions.cs:53`,
    present wherever Data Protection is added.
  - **Web host only:** `self` (`live`, `startup`) — `src/Hosts/Tailor360.Web/Program.cs:94-97`.
  - **Worker host only:** `self` (`live`, `startup`) and `HeartbeatHealthCheck` (`ready`) —
    `src/Hosts/Tailor360.Worker/Program.cs:85-87`.
- `src/Platform/Tailor360.Platform.Security/Permissions/PlatformPermissions.cs:50` — `HealthRead = "admin.health.read"`,
  `PermissionScope.Organisation`, no MFA, no step-up, no reason. Already granted in
  `src/Modules/Identity/Tailor360.Modules.Identity.Application/Access/SystemRoles.cs:86,141`.
- `src/Modules/Identity/Tailor360.Modules.Identity.Api/Administration/` — `AuditAdminEndpoints.cs`,
  `OutboxAdminEndpoints.cs`, `FeatureFlagAdminEndpoints.cs`. This is the established home for a platform-administration
  HTTP surface, and where the authorised variant of this route belongs if it is not mapped from the host.
- `src/Platform/Tailor360.Platform.Security/Endpoints/` —
  `EndpointAuthorisationExtensions.cs`, `RateLimitPolicyNames.cs` and `RequestTimeoutPolicies.cs`:
  `RequirePermission`, `RateLimitPolicyNames.DefaultUser` ("default-user"), `RequestTimeoutPolicies.Read` ("read").

## What is missing

- The route itself, on both hosts.
- A detail payload. `HealthResponseWriter` emits name and status only; the detail report owes each check's
  `Description`, `Duration` and its tags, and the host's build version.
- Any probe that maps `HealthCheckTags.NonEssential`. `HealthEndpointExtensions.MapTailor360HealthEndpoints` maps
  `Live`, `Ready` and `Startup` only (lines 31-33), so `OutboxBacklogHealthCheck` and `AuditPartitionHealthCheck`
  execute — `MapHealthChecks` runs the whole `HealthCheckService` and filters the *report* by predicate — and their
  statuses are discarded. Two checks run on every probe request to nowhere.
- **Four test-side guards that a new `/health/` route trips, all of which must be handled in this pull request.**
  Read each before writing the route; three of them will otherwise either fail the build for the wrong reason or, worse,
  silently exempt the new route from the rule it is supposed to prove:
  1. `tests/Tailor360.ContractTests/EndpointInventoryTests.cs:73` asserts
     `routes.Count(route => route.IsHealthProbe).ShouldBe(3)` — a hard count. `IsHealthProbe` is derived from
     `HealthProbeMetadata` (`PublishedEndpointInventory.cs:167`), so **do not attach `HealthProbeMetadata` to the detail
     route**: it is not an orchestrator probe, and attaching it both breaks this count and exempts the route from
     ARCH-017 through `RateLimitPolicyInspector.cs:42,74`.
  2. `tests/Tailor360.ContractTests/PublishedEndpointInventory.cs:109-120` raises `undeclared-exclusion` for any route
     that carries `ExcludeFromDescription` without `InternalEndpointMetadata`. So the detail route must declare
     **`.InternalEndpoint(reason, reviewedIn)`** from
     `src/Platform/Tailor360.Platform.Security/Endpoints/InternalEndpointExtensions.cs` — the reason must be **longer
     than 20 characters** and `reviewedIn` non-blank, per `EndpointInventoryTests.cs:59-62`. Follow the four existing
     examples at `src/Hosts/Tailor360.Web/Program.cs:199,216,227,243`.
  3. `tests/Tailor360.ContractTests/EndpointPolicyTests.cs:109-110` exempts **every** path beginning `/health/` from the
     ARCH-007 check by prefix. Left as it is, this issue's whole point — that the route is permissioned — is untested.
     **Narrow `IsHealthProbe` to the three literal probe paths** (`HealthEndpointExtensions.LivePath`, `ReadyPath`,
     `StartupPath`), and keep the negative control at `EndpointPolicyTests`' end passing.
  4. `tests/Tailor360.IntegrationTests/Authorization/EndpointInventory.cs:110-115` classifies by **permission first**
     and only falls back to the `HealthProbePrefix = "/health"` path rule, so a permissioned `/health/detail` is
     correctly classified `permission` and **does** demand a matrix row — no change needed there, but the
     `HealthProbePrefix` doc-comment at lines 36-42 calls the prefix "the matrix's one standing exemption" and is no
     longer true; correct the comment.
- The authorisation register rows. `docs/architecture/architecture-rules.md` ARCH-007 "Allowed exceptions" names
  "`/health/live`, `/health/startup`, `/health/ready` and `/health/detail`", and the section 4 exception register says
  "The four health probes under `/health/`" — both are wrong once the detail route is permissioned rather than
  anonymous, `docs/architecture/architecture-rules.md` line 184 (the ARCH-007 "Allowed exceptions" cell) and line 359
  (the section 4 exception register, "The four health probes under `/health/`") are both wrong once the detail route is
  permissioned, and `docs/security/permission-matrix.md` line 508 routes `/health/{**path}` to `anonymous` — the new row
  must sit **above** that fallback row so the generated block reads in route order.

## Acceptance criteria

- [ ] An `owner` or `admin` session calling `GET /health/detail` on the web host receives 200 with every registered
      check named, each with its status, duration and description, and the build version.
- [ ] The route declares a permission, exactly one rate-limit policy and a request-timeout policy, and is absent from
      `docs/api/openapi.v1.json` because it carries `.ExcludeFromDescription()` **and** `.InternalEndpoint(...)` —
      `EndpointInventoryTests.EveryPublishedEndpointAppearsInTheApiDocument` and
      `EveryInternalEndpointRecordsAReasonAndAReview` are the two tests that prove it, and both must be green without
      `docs/api/openapi.v1.json` or `clients/pwa/src/api/schema.d.ts` changing by a byte.
- [ ] **Negative:** an anonymous caller gets `401 security.authentication-required`; a signed-in caller without
      `admin.health.read` gets `403 security.forbidden`; both answers are the shapes named in the `answers` block of
      `tests/Tailor360.IntegrationTests/Authorization/matrix.yaml`, and neither response body names a host, a connection
      string, a dependency version or an exception message.
- [ ] **Negative:** the three anonymous probes are unchanged — `/health/ready` still reports the database only, and
      `/health/live` still performs no dependency call. A test asserts that a failing non-essential check leaves
      `/health/ready` at 200 and `/health/live` at 200 while `/health/detail` reports that check `Degraded`.
- [ ] **Exception:** with the database unreachable, `/health/detail` answers `503` with the database check `Unhealthy`
      and still renders every other check rather than failing to render at all; and on the worker host the detail route
      answers on port 8081 without a session and is not reachable through the reverse proxy.
