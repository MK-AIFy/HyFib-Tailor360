Sub-issue of #36. Follows E07-F02-2, which ships the camera engine with no screen. **This issue is the first screen
in the area and the area's message family**: the **Scanner check** page under Settings, which decodes any barcode
and shows what it read **without resolving and without committing anything**, plus
`clients/pwa/src/i18n/messages/scanning.ts` and the Storybook file every later child of #36 adds to.

It is its own session rather than a section of E07-F02-2 because a route with five states, a bilingual message
family and a stories file is most of a session on its own: `clients/pwa/src/routes/catalog/
CatalogVersionEditorRoute.tsx` is 994 production lines for one route, before its entry components, its API module,
its messages and its stories. It is the **cheapest possible consumer of the camera** — plan Section 8 for #36
defines it as decoding "any barcode … without resolving or committing", and adds that it is "used for device setup,
print-quality checks and support" — so this pull request is reviewable end to end with no resolve endpoint, no
permission and no custody state anywhere in it.

## Acceptance criteria

- [ ] A decode from the fake camera source and a wedge burst both appear in the table with raw, normalised,
      namespace, check-character validity, source and decode latency, and **no network request is made in either
      case** — asserted by a `fetch` stub that fails the test if it is called.
- [ ] The screen is reachable **without a session**: a test renders it with no `SessionProvider` and it works, which
      is the behaviour its router placement promises.
- [ ] **Negative:** each of the five reason codes renders its own `ErrorState` with its own copy; the four camera
      ones do not collapse into one "camera unavailable" message, because the remedies differ.
- [ ] **Negative:** a payload with a corrupted check character is **displayed** with `checksumValid: false` rather
      than hidden or refused — this screen's job is to report what was read, and INV-BID-07 puts validation on the
      server in any case.
- [ ] **Negative:** a `gs1` digit string is shown as `gs1` and not as malformed.
- [ ] **Exception:** with no camera at all, the screen still accepts a wedge burst and a typed payload, and says
      that the camera is unavailable rather than appearing broken (`support-matrix.md` section 6, print-station and
      camera-less desktop rows).
- [ ] The viewfinder is a dialog: announced as one, `Escape` closes it, focus returns to the control that opened it
      (**A11Y-SC-06**), and it says what to do while open (**A11Y-SC-07**).
- [ ] Leaving the screen stops the camera — no light stays on — asserted on the fake track.
- [ ] Every string is a `scanning.*` id present in **both** `scanningEn` and `scanningTa`; `typecheck` is the gate.
      Decode latency is rendered through `getFormatters()`.
- [ ] No axe violation in the idle, decoded and each error state; no horizontal overflow at
      `expectNoHorizontalOverflow`'s **default** widths and zoom levels; every control ≥ 48 × 48 px.

## Permissions and roles

**No permission is added and none is required**, and that is a decision rather than an omission: gating a device
diagnostic behind `custody.scan` would stop the person setting a device up from testing it, and the screen exposes
nothing the operator is not already holding. The route is therefore outside both `RequireSession` and
`RequirePermission`, exactly like `settings/display`, and the **Forbidden** column of the states table below says
"not applicable" rather than being left blank.

No endpoint is published, so ARCH-007, ARCH-008, ARCH-017 and ARCH-023 have nothing to bind to here.
`docs/security/permission-matrix.md` and `tests/Tailor360.IntegrationTests/Authorization/matrix.yaml` are
**untouched** — both are single-session files and this issue keeps away from them.
