Sub-issue of #46. Eighth of thirteen: the controls that keep a month-end export off the counter's neck — the estimated
row-count refusal with the asynchronous path offered, bounded per-branch and global export concurrency with a queue
limit that answers "queued" rather than doing more work, and cancellation of a long-running export. It is the
"isolation of reporting load" bullet of the plan's #46 blueprint, and it is split out because it is a concurrency and
configuration slice with no projection, no payload shape and no screen of its own.

  and the `t360_reporting` role running `default_transaction_read_only` (`module-ownership.md` section 5.9).
- #186 — `export_jobs` with its `status`, the worker generation path, and the synchronous-versus-asynchronous split
  behind a row limit. This child supplies the **limit enforcement, the queue and the cancellation**, and must extend

- `src/Platform/Tailor360.Platform.Security/Endpoints/RequestTimeoutPolicies.cs` — `Report` and `Export` already

  that comment before designing cancellation.**

  catalogued; the numbers behind the name belong to the host and to #53/#19, not to this child.

## What is missing

- Nothing estimates a report's row count before running it, so a large range is either served or times out.
- There is no export queue, no per-branch or global concurrency bound and no cancellation: grepping
  `src/Modules/Reporting` for "queue" and for "concurrency" returns nothing, because the module has no code.
- `tests/load/` does not exist — `ls tests/` returns the four .NET test projects and `fixtures` (which itself holds
  only `billing`) — and `./scripts/dev test` accepts `all`, `unit`, `architecture`, `contract`, `integration`, `pwa`
  and `e2e` and **no `load` tier**: the `*)` branch of `cmd_test` in `scripts/dev` prints exactly that list in its
  failure message. `tests/e2e` does not exist either, which is why the `e2e` tier is a no-op today. The k6 harness
  arrives with #58, which is why the mixed-load **run** is a recorded deferral below rather than a checkbox here.

## Scope

- [ ] **Estimated row count before execution** for every report route of `e10-f03-3` and `e10-f03-6`: a cheap estimate
      from the projection's own statistics or a bounded count, compared with the synchronous limit derived from the
      sourced 50,000-row cap. Above the limit the synchronous request is **refused** with an RFC 9457 problem carrying
      a stable code (for example `reporting.range-too-large`), the estimated count, the limit, and the asynchronous
      path to use — never a truncated answer and never a silent sample.
- [ ] **The limit and the concurrency bounds as configuration**, not constants: one section (`Reporting:Exports:…`)
      holding the synchronous row limit, the per-branch concurrent-export bound, the global bound and the queue depth,
      each **defaulted from the capacity document rows quoted above** and each documented in `docs/platform/` or the
      module's own README with the row it came from. DOR-11: configuration, versioned, with no seeded value that has
      no source.
- [ ] **A bounded export queue in the worker**: claims of `export_jobs` are limited per branch and globally; beyond
      the bound a request is **accepted and queued** with its position, and beyond the queue depth it is refused with
      a problem code saying so and when to retry — "queued rather than more work", exactly as the blueprint says.
      Claims take a lease so a second worker replica needs no code change.
- [ ] **Cancellation**: a requester may cancel their own queued or running export — `POST
      /api/v1/reporting/exports/{id}/cancel`, `.RequirePermission(ReportingPermissions.Export,
      BranchScope.CurrentBranch)`, `.RequireRateLimiting(RateLimitPolicyNames.Write)`,
      `.WithRequestTimeout(RequestTimeoutPolicies.Command)`, `.Audited("reporting.report_export.cancelled")`
      (ARCH-008), `.RequireIdempotency()`, and **`.ScopedToResource(ReportingResourceKinds.ExportJob, "id")`** because
      the route is branch-scoped and takes a parameter, which is exactly what ARCH-023 catches
      (`tests/Tailor360.ContractTests/EndpointResourceScopeTests.cs`). **Check #186 first**: if it already declares a
      `ReportingResourceKinds` constant and an `IResourceScopeResolver` for `export_jobs`, reuse them unchanged; if
      not, add both here, following
      `src/Modules/Billing/Tailor360.Modules.Billing.Application/Invoicing/BillingResourceKinds.cs` and
      `src/Modules/Billing/Tailor360.Modules.Billing.Infrastructure/Invoicing/InvoiceScopeResolver.cs`, resolving the
      branch from `export_jobs` alone, and register the resolver in `ReportingModuleServiceCollectionExtensions`. A
      cancelled job stops at the next checkpoint, leaves no downloadable file and leaves the row in a terminal
      cancelled state. One route, one matrix section 5 row, one `matrix.yaml` `identifier-editing` entry for `{id}`
      recording that a foreign export and an unknown one are both `404 security.resource-not-found`.
- [ ] **Interactive-versus-asynchronous separation proven, not asserted**: an integration test that runs a large
      export while an interactive report read and a transactional write proceed, and asserts the interactive work is
      not blocked and the reporting statement timeout is what stops a runaway query. This is the deterministic half of
      the parent's fifth acceptance criterion; the measured half is #58's k6 run.
- [ ] **The S4 scenario recorded where #58 will pick it up**: a short specification of scenario S4 for these exports
      added beside the capacity document's section 6 row — the scenario already exists there, at line 318: "The
      monthly GST summary, the valuation run and 5 concurrent 50,000-row exports while S1 runs" — and named in the
      deferral record below, so the k6 sibling of #58 implements one scenario rather than inventing it. **No k6 file
      is added here**, because `tests/load/lib` does not exist yet and a scenario without the harness cannot run.
- [ ] Regenerate `docs/api/openapi.v1.json` and `clients/pwa/src/api/schema.d.ts` for the one new route.

## Acceptance criteria

- [ ] A synchronous report request whose estimated row count exceeds the configured limit is refused with `400`-class
      RFC 9457 problem details carrying the code, the estimate, the limit and the asynchronous path — and the test
      asserts the response is a problem document, not a truncated result set.
- [ ] With the per-branch bound at its configured value, an additional export for that branch is **queued** with its
      position rather than started, and the first completion starts it.
- [ ] Beyond the configured queue depth a request is refused with a distinct problem code that says when to retry;
      nothing is dropped silently and no job row is left in a non-terminal state.
- [ ] A cancelled export stops at its next checkpoint, offers no download, ends in a terminal cancelled state, and
      writes its audit entry; cancelling twice with the same `Idempotency-Key` returns the first outcome.
- [ ] **Negative:** a caller cancelling **another** requester's export is refused — `403 security.forbidden` for a
      caller in the same branch without the right, and **404** for an export belonging to another branch, per the
      `identifier-editing` convention in `tests/Tailor360.IntegrationTests/Authorization/matrix.yaml`.
- [ ] **Negative:** an interactive report query held past the reporting `statement_timeout` is cut off and the
      connection released, proven by a test (this is #183's control, asserted here for an export-shaped query).
- [ ] **Exception:** a worker restart mid-export leaves the job claimable again by lease expiry, and the restarted run
      produces one file and one audit entry, not two.
- [ ] The new route declares exactly one permission, one rate-limit policy, a resource scope and an audit action, and
      has exactly one row in permission-matrix section 5.
